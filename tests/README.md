# Glyphbridge tests

Standard library only. FontLab and the MCP SDK are **stubbed**, so these run anywhere (including a Claude sandbox). The current versions and the expected line counts of the four harnesses are in [CURRENT-STATUS.md](../mental-model/CURRENT-STATUS.md). A plain run on an earlier Windows machine once showed one FAIL in `create_unicode_tests.py` that was purely a non-UTF-8 console code page turning a printed `é` into a replacement character; `run_all.py` now starts the harnesses with UTF-8 output (`PYTHONUTF8=1`, `PYTHONIOENCODING=utf-8`), which removed it. If a diff ever shows `�` in the "now" lines, it is this encoding problem: do NOT use `--update`.

    python tests\run_all.py            # check; exit code 0 = everything as expected
    python tests\run_all.py --update   # after REVIEWING a legitimate change, re-save the expected output

**Location (fixed):** `<repository folder>\tests\`, inside the project folder, right next to `venv\`,
`glyphbridge_mcp_server.py` and a copy of `glyphbridge_fontlab_mcp_listener.py`. Run the command above from the project folder. The harnesses
read both scripts from the PARENT of `tests\` first (then `tests\` itself, then the current folder), so a stray copy inside
`tests\` is ignored while the project-folder copy exists.

**Two homes of the listener:** FontLab runs it from `...\Documents\FontLab\FontLab 8\Scripts\`; the tests read the copy in the
project folder. `run_all.py` prints which files it tested and compares the project copy with the one in that Scripts folder (set
`GLYPHBRIDGE_FONTLAB_SCRIPTS` if yours is elsewhere): identical -> a note, different -> a WARNING (it never fails the run), missing ->
a note. After any listener change, copy the tested file into the Scripts folder and restart the listener. It also warns if a file
with a pre-rename name (`glyphbridge_listener.py`, `glyphbridge_server.py`) still exists in the project folder, in `tests\` or in the
Scripts folder: delete such files, because a stale copy could be started by habit.

`run_all.py` also prints the Python version. It **stops with `ERROR` (exit code 2, nothing tested)** if either script is missing from the project
folder, and on a harness that crashes it shows the last lines the harness printed. It runs the harnesses with `-B`, so no `__pycache__` is created
(if one appears anyway it is harmless and can be deleted; never attach it to a chat).

The checks are **print based**, not assertions: a change shows up as a diff against the expected output, so review the diff before
using `--update`. Adding a case: append it to the relevant script, run, review, `--update`.

What these tests do NOT cover: real FontLab behaviour (that needs the live checks in sections 7 and 12 of the milestone summary and scenarios 16, 18 and 19 of the checklist), the
MCP SDK plumbing (stdio, tool registration), and real latency.
