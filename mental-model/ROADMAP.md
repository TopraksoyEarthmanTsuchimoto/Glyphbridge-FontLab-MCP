## 11. Known limits and untried ideas

- **Components** are read on the modern-first route with their nodes where FontLab draws them, labelled and naming their source (listener 0.128 / server 0.49), and since 0.130 / 0.50 checked against their source's box, for plain offsets only; the source's outline is not read separately, and rotation and other transforms are untested. A tool edit of a source may not reach the glyphs using it ([topics/reading.md](topics/reading.md)). `GlyphComponent` and the contents of `glyph.components` and `flLayer.components` are untried; only `len(glyph.components)` and `componentsCount()` are in use, and the names and docstrings are read (604, 605). This is the biggest READING gap for real fonts (accented letters are usually composites): section 14 P1.
- **Open contours** are read from the modern layer since server 0.46 (live 584, 585); the legacy route still assumes closed contours (untested with open ones); since listener 0.126 / server 0.47 `draw_path` draws open contours too (live 595–603); what FontLab does with them on export is untested. **Several elements** in one glyph: contours are assigned to elements in FontLab's listed order, confirmed only by simulation plus the combined bbox/margin agreement.
- **Power Brush:** only the generated outline is read (shape flagged composite); skeleton/stroke settings are not exposed.
- **Rotation and mirroring** on real data: simulated only. **Multi-layer / multi-master:** untested (only the layer `test_font` of the user's font has been seen).
- **Large glyphs:** evidence in hand (v8): 180 nodes drawn and read back completely, 990 nodes drawn (`nodes_match`, margins agree), `get_glyph_sidebearings` fine on it. NOT tested: a request near the 2000-node cap, the outline route on 1000+ nodes against the 5 s timeout, real timings in seconds (the tools show none), `_MODERN_OUTLINE_MAX_NODES = 5000`. Decision of the user (v8): all tests with glyphs of more than about 150 nodes are postponed to the VERY END (section 14, block LAST).
- **Straight-line-only and multi-contour glyphs** are read and written live: square with a hole (`ringtest`), an O with a counter (GUI-confirmed, section 8j), a diagonal circle, an S-like blob. A real designed letter READ from a real font (many curves, hints) is still unchecked (read-only reads of a few glyphs of the Arial font opened from the system are a cheap next step, section 14 P1).
- **Saving is deliberately NOT offered** (save policy, section 2: nothing calls `font.save()`, a test guards it; the person saves). Geometry is written only through the drawing, width and sidebearing tools of sections 8b to 8d and 8g (`shapeData.addContour` + `layer.addShape`, `setSB`, `advanceWidth`); `createContour/deleteContour` untried; there is NO tool that edits or removes an existing outline.
- **No tool lists every glyph's codepoint:** an agent learns who holds a codepoint only from `create_glyph` / `set_glyph_unicode` replies.
- TypeRig was deliberately not adopted. FontLab docs: https://fontlabcom.github.io/fontlab-python-docs/ (`fgFont`, `fgLayer`, `fgGlyph`).
- **Limits of the drawing tools (v0.82 / v0.26):** `draw_polygon` straight segments only; `draw_path` straight and CUBIC segments; `draw_polygon` closed contours only, `draw_path` closed and, since listener 0.126 / server 0.47, open ones; ONE shape only (several contours in one shape work; several separate shapes do not), only into an EMPTY glyph, whole units only (rule B). `verified` covers straight, cubic and, since server 0.43, quadratic outlines; a contour that mixes cubic and quadratic points is `unverified`. Cubic output was tested only in the cubic test font. `set_glyph_sidebearings` / `set_glyph_width` on a curved glyph are now tested live (v8). Drawn geometry came back exactly after a save and reopen of the font (709); kerning writes too (557–560, 577, 717, 721).
- **Reader limits (v8):** `get_glyph_outline` costs about 65 tokens per node and has no summary mode; the legacy route can be stale after API writes and is only FLAGGED by v0.25+, not corrected (section 8i); the smooth gate checks the ROUNDED handles, so very short handles on smooth nodes may be refused (computed, not tried live).
- **New-font and guard limits (v9):** there is no create-font tool; the guard remembers only this listener run's changes and skips refreshes while anything is unsynced (the grid / glyph list may then lag until the person opens a glyph); server replies show the guard fields only from v0.27; drawn geometry has not been tested after a save and reopen (save tests run only by preference, [DECISIONS.md](DECISIONS.md)).
- **Sync and new-font limits (v10):** the auto sync is proven for a new unsaved font and for a font opened from a file, on NEW glyphs, in a font with a single layer `test_font` / `Regular`; and for a glyph whose editor tab is open (T3, tests 256–258, sidebearings); and for width and sidebearings on an existing glyph with a legacy layer (T4, tests 145a–g, 259 and 260; a plain contour and a Power Brush shape). NOT proven for multi-layer glyphs, quadratic fonts, big glyphs, or after File > Save (not run; save tests by preference only). The legacy width route and `create_glyph` / `delete_glyph` / `set_glyph_unicode` do not sync anything themselves (they only run their update when the guard allows it). A failed sync has been seen in stubs only. There is still no create-font tool (only the debug probe, once per listener run). The `/debug/trymodern` `create` stage is untested live.
- **Disposable fonts for live tests:** a new unsaved font (File > New Font, or `flPackage()` through `/debug/tryfont`: "Unnamed Regular", upm 1000, master `Regular`) or, until the move below is finished, the local test font `savedtestfont.vfc` (glyphs `.notdef`, `A` (Power Brush), `testglyph1`..`testglyph4`; layer `test_font`; upm 1000, ascender 750, descender -250, cap height 700, x-height 500). The test font is never saved after a test, and FontLab is quit without saving. Test glyphs vanish at the next FontLab restart, so each round uses a NEW name prefix.
- **Goal: no test needs `savedtestfont.vfc`** (decision of 2026-11-01). Every live test that uses it (Appendix A1 / test 142, T4 / test 145, the reference glyphs of the scenario checklist) gets a short recipe that builds its reference glyphs in a fresh disposable font: a new font, the drawing tools, or a few GUI steps (the Element tool for a transform, Power Brush for `A`). The captured node data the stub tests need is already embedded in `tests/server_analysis_tests.py`.

- **Font-info limits (listener 0.118 / server 0.41):** the PostScript names come from the font package only when it is matched to the font (the only font, or the same non-empty path); with two unsaved fonts the legacy `font.info` is reported instead, with a note. Family, style and the other `font.info` fields are still read from the legacy view, which lagged behind Font Info for the PostScript name (298); whether they lag too is untested ([WATCH-POINTS.md](WATCH-POINTS.md)). Whether a name was typed by a person or filled in by FontLab is not known.
- **Kerning limits (listener 0.104 / server 0.33):** only the current master's table is read (`flPackage.kerning(master)`) of the font in front; with several fonts open only when its path matches (0.112). Feature-based (GPOS) kerning, contextual kerning and other masters are NOT covered (in Arial the `kern` feature agrees with the table in all 20 pairs compared, K11, [topics/kerning.md](topics/kerning.md) §11). Group membership is used inside the read but cannot be listed yet (P1.6, required by the user). "All pairs of one glyph" and the whole table cannot be read (deliberate). Text mode maps characters through the primary Unicode only. Defects A and B are fixed (P0.8). Timings are measured on Arial only (K14: under 0.1 s for 2,000 pairs); files other than Arial and the test fonts, are untested, and the 1 MB body limit is stub-tested only (K15 dropped); FontLab's order of entries is proven (§9.9). Since listener 0.124 / server 0.44 `set_kerning` writes glyph : glyph pairs of the current master (P2.9; live 565–577); it cannot write classes or other masters or remove a pair, and FontLab's KERNING panel shows its pairs only after a switch to another font and back, or after save and reopen. Since listener 0.105 every product route uses `CountFonts() == 0` for "no font open" (P0.2).
