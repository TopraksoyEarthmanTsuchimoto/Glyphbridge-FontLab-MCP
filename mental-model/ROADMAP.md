## 11. Known limits and untried ideas

- **Components** are read on the modern-first route with their nodes where FontLab draws them, labelled and naming their source (listener 0.128 / server 0.49), and since 0.130 / 0.50 checked against their source's box, for plain offsets only; the source's outline is not read separately; rotation reads `verified` (765–771), and mirroring, slant and vertical scale are untested. A tool edit of a source may not reach the glyphs using it ([topics/reading.md](topics/reading.md)). `GlyphComponent` and the contents of `glyph.components` and `flLayer.components` are untried; only `len(glyph.components)` and `componentsCount()` are in use, and the names and docstrings are read (604, 605). This is the biggest READING gap for real fonts (accented letters are usually composites): section 14 P1.
- **Open contours** are read from the modern layer since server 0.46 (live 584, 585); the legacy route still assumes closed contours (untested with open ones); since listener 0.126 / server 0.47 `draw_path` draws open contours too (live 595–603), and they came back unchanged after a save and reopen (755–764); on export (TrueType and OpenType PS, default settings) FontLab drops them without a warning (779–791). **Several elements** in one glyph: contours are assigned to elements in FontLab's listed order, confirmed only by simulation plus the combined bbox/margin agreement.
- **Power Brush:** only the generated outline is read (shape flagged composite); skeleton/stroke settings are not exposed.
- **Rotation** on real data: components read live (765–771). **Mirroring** on real data: simulated only. **Multi-layer / multi-master:** untested (only the layer `test_font` of the user's font has been seen).
- **Large glyphs:** evidence in hand (v8): 180 nodes drawn and read back completely, 990 nodes drawn (`nodes_match`, margins agree), `get_glyph_sidebearings` fine on it. NOT tested: a request near the 2000-node cap, the outline route on 1000+ nodes against the 5 s timeout, real timings in seconds (the tools show none), `_MODERN_OUTLINE_MAX_NODES = 5000`. Decision of the user (v8): all tests with glyphs of more than about 150 nodes are postponed to the VERY END (section 14, block LAST).
- **Straight-line-only and multi-contour glyphs** are read and written live: square with a hole (`ringtest`), an O with a counter (GUI-confirmed, section 8j), a diagonal circle, an S-like blob. A real designed letter READ from a real font (many curves, hints) is still unchecked (read-only reads of a few glyphs of the Arial font opened from the system are a cheap next step, section 14 P1).
- **Saving is deliberately NOT offered** (save policy, section 2: nothing calls `font.save()`, a test guards it; the person saves). Geometry is written only through the drawing, width and sidebearing tools of sections 8b to 8d and 8g (`shapeData.addContour` + `layer.addShape`, `setSB`, `advanceWidth`); `createContour/deleteContour` untried; there is NO tool that edits or removes an existing outline.
- **No tool lists every glyph's codepoint:** an agent learns who holds a codepoint only from `create_glyph` / `set_glyph_unicode` replies.
- TypeRig was deliberately not adopted. FontLab docs: https://fontlabcom.github.io/fontlab-python-docs/ (`fgFont`, `fgLayer`, `fgGlyph`).
- **Limits of the drawing tools (v0.82 / v0.26):** `draw_polygon` straight segments only; `draw_path` straight and CUBIC segments; `draw_polygon` closed contours only, `draw_path` closed and, since listener 0.126 / server 0.47, open ones; ONE shape only (several contours in one shape work; several separate shapes do not), only into an EMPTY glyph, whole units only (rule B). `verified` covers straight, cubic and, since server 0.43, quadratic outlines; a contour that mixes cubic and quadratic points is `unverified`. Cubic output was tested only in the cubic test font. `set_glyph_sidebearings` / `set_glyph_width` on a curved glyph are now tested live (v8). Drawn geometry came back exactly after a save and reopen of the font (709), open contours too (755–764); kerning writes too (557–560, 577, 717, 721).
- **Reader limits (v8):** `get_glyph_outline` costs about 65 tokens per node and has no summary mode; the legacy route can be stale after API writes and is only FLAGGED by v0.25+, not corrected (section 8i); the smooth gate checks the ROUNDED handles, so very short handles on smooth nodes may be refused (computed, not tried live).
- **New-font and guard limits (v9):** there is no create-font tool; the guard remembers only this listener run's changes and skips refreshes while anything is unsynced (the grid / glyph list may then lag until the person opens a glyph); server replies show the guard fields only from v0.27; drawn geometry came back exactly after a save and reopen of a font made with File > New Font (709, 755–764) and of a font made by `flPackage()` (772–778).
- **Sync and new-font limits (v10):** the auto sync is proven for a new unsaved font and for a font opened from a file, on NEW glyphs, in a font with a single layer `test_font` / `Regular`; and for a glyph whose editor tab is open (T3, tests 256–258, sidebearings); and for width and sidebearings on an existing glyph with a legacy layer (T4, tests 145a–g, 259 and 260; a plain contour and a Power Brush shape). NOT proven for multi-layer glyphs, quadratic fonts or big glyphs. After File > Save and reopen, proven for synced tool-made glyphs of a font made with File > New Font (707–712, 755–764). The legacy width route and `create_glyph` / `delete_glyph` / `set_glyph_unicode` do not sync anything themselves (they only run their update when the guard allows it).
