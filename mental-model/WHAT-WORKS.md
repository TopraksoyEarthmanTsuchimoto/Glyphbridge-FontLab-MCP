# What works

What is live-proven in FontLab, and which version each feature needs. An entry is added only after a live run; what is stub-tested only is named as such. What is not proven or not built, and what comes next: [CURRENT-STATUS.md](CURRENT-STATUS.md). This file is not a startup core file: [AGENTS.md](../AGENTS.md) says when to read it. Word budget: 1,500 ([MARKDOWN-MAP.md](MARKDOWN-MAP.md)).

## Live-proven in FontLab

- **Reading:** outlines with element transforms (scale, offset, slant), cubic and quadratic outlines, Power Brush output, widths, sidebearings, the stale-view fallback; since 0.120 / 0.42 a glyph with modern nodes from the modern layer only, its transforms applied, checked horizontally (497–520); since 0.121 / 0.43 checked vertically too, against FontLab's `inkBox()`, and quadratic outlines from their exact extents (INK 521–533, V121 534–541); since server 0.46 open contours, straight and cubic, `verified` with an `svg_path` without Z and no direction (OC 579–585). → [topics/reading.md](topics/reading.md)
- **Components, partly** (one master, 606–656): one component, identity, offset and horizontal scale read `verified`; two components in a glyph and one source shared by two glyphs read correctly (627–636). Since 0.128 / 0.49 `get_glyph_outline` labels a component and names its source (624–626). Since 0.130 / 0.50 an accent inside its base reads `verified` element by element (652), and a component found behind its source reads `unverified` (651, 653; plain offsets only). Not proven: rotation and the other transforms, other masters. No tool places a component. → [topics/reading.md](topics/reading.md)
- **Writing:** create and delete glyphs (name safety rules), Unicode set and clear, width, sidebearings, closed straight and cubic contours into an empty glyph, since 0.126 / 0.47 open ones too, alone or with closed ones (OT 595–603), auto sync after every modern write, also with the glyph's editor tab open (T3, 257) and on an existing glyph with a legacy layer, in a font opened from a file (T4, 145a–g, 259, 260: a plain contour and a Power Brush shape). → [topics/geometry.md](topics/geometry.md), [topics/names-unicode.md](topics/names-unicode.md), [topics/fonts-and-sync.md](topics/fonts-and-sync.md)
- **Save reminder:** `finish_changes` through the Desktop chat (T2, 253–255): one request with three verified writes ended with one bold reminder, a read-only request with none; FontLab showed LSB 50, width 400, RSB 50 as reported.
- **Save question** (S1, 657–691c): since 0.132 / 0.51 a verified, synced glyph write turns FontLab's changed icon blue: `create_glyph` (668, 669), width, sidebearings, `draw_polygon`, `draw_path` and Unicode (677–681). Since 0.133 / 0.53 a verified delete does too, through one surviving glyph (688). FontLab's question on close was seen after every one of these (668, 669, 682, 688, 698–701). On a Power Brush glyph, width, sidebearings and Unicode turned the icon blue and kept the brush and its fractions (693–695). With two fonts open, five glyph writes marked only the font in front (702–706). Since 0.134 / 0.54 a `set_kerning` that changed an entry is marked through a glyph of a changed pair, and FontLab asked (718, 719); before 0.136 / 0.56 the icon usually needed a hover there (719, 722, 723, 725, 726), and since then it went blue at once (748–753, [DECISIONS.md](DECISIONS.md)). Not marked: a delete that leaves only `.notdef` (689), `create_glyph` with no layer (691a). → [topics/server-and-endpoints.md](topics/server-and-endpoints.md) §2
- **Save and reopen** (707–712, one master, a font made with File > New Font): saved at FontLab's question and reopened, tool-made plain glyphs came back exactly: nodes, widths, sidebearings, Unicode. A Power Brush glyph kept its advance, offset, Unicode, node count and brush element, but nearly all its nodes changed by under one unit at load, also on a glyph no tool wrote to. → [topics/reading.md](topics/reading.md) §8p
- **`.notdef`** check and one-time dialog. → [topics/notdef.md](topics/notdef.md)
- **Activity log** in FontLab's OUTPUT panel: one line per change and one summary of reads, naming the client (`local-agent-mode`) and, once, the program that started the server (`| CLAUDE`); live tests 190, 191, 225–229, 236–242. Stub-tested only: REFUSED / FAILED lines, unsynced or warned results, the `writes` / `off` modes, the flush at `/shutdown`. → [topics/server-and-endpoints.md](topics/server-and-endpoints.md) §4
- **No font open** (P0.2): with the only font closed in a running FontLab, `fontlab_status` gave `font_open: false`, and a width read and a create were refused; Arial reopened read as before (227, 228). In a freshly started FontLab (K13, 244) all 8 read routes answered `open: false`, the placeholder glyph `Paper` included, with no dialog. Not seen live: the other write tools (stub only). → [topics/fonts-and-sync.md](topics/fonts-and-sync.md)
- **Several fonts open** (T5, 262–331): every tool follows the font window in front, every reply names its font, and a switch is reported in the next reply, also after an error; `get_kerning` refuses an unsaved font in front. With three fonts, `draw_path` and the reads other than `list_glyphs` and `get_glyph_width` are untested; `get_kerning` is proven only in refusing an unsaved font in front (268). → [topics/fonts-and-sync.md](topics/fonts-and-sync.md)
- **Kerning** (K1–K14 and K16, 2026-11-01 to 2026-11-03, each test in [LIVE-TESTS.md](LIVE-TESTS.md)): **since 0.104 / 0.33** `get_kerning` reads the current master's table and reports each value's `source` (live 219–223); with several fonts open it reads the font in front, matched by path, and names it (0.112 / 0.37, 265–268). Proven: GET and POST, the agent reading only the pairs it needs and asking above 250, `text` mode equal to the KERNING panel with its special characters, errors never read as zero, an exception winning over its class, a FontLab text line and Arial's `kern` feature agreeing with the table, an empty table, timings up to 2,000 pairs. → [topics/kerning.md](topics/kerning.md) §10, §11

- **Kerning writes:** `set_kerning` writes glyph : glyph pairs of the current master, in whole units, verified by a re-read and saved like GUI pairs (research 542–564, live 565–577). Since 0.136 / 0.56 a write that changed an entry asks FontLab to refresh its KERNING panel, which then showed new pairs and new values at once (744, 745), with two fonts open (747, one run) and in a freshly started FontLab (748); the changed icon went blue at once in 748–753, with no hover. Without that call the panel shows them only after a switch to another font and back, or a save and reopen. Classes, other masters and large fonts are untested. Before 0.134 / 0.54 closing asked no save question and lost them (561, 562), since then see the save question above; Undo cannot take them back. → [topics/kerning.md](topics/kerning.md) §13, §14

- **Font names** (291–302): FontLab keeps the names Font Info shows in the font package (`psn`, `ffn`, `tfn`, `tsn`, `sgn`); the legacy `font.info` the tools read before can disagree (298). Since listener 0.118 `/font/current` reads the package when it is matched to the font (302), and says why when it is not (301); `get_current_font` reports them since server 0.41 (303). The delete dialog names the client as sent and the font, and the save reminder uses the system's shortcut (0.114 / 0.40, 304–308, [CHANGELOG.md](CHANGELOG.md)). → [topics/fonts-and-sync.md](topics/fonts-and-sync.md)

## Which version each feature needs

`get_kerning` needs listener 0.104 (server 0.33); with several fonts open, 0.112 / 0.37. The PostScript names from the font package need 0.118 / 0.41; the F1 fix, 0.120 / 0.42; the vertical check against `inkBox()` and exact quadratic extents, 0.121 / 0.43. Listeners 0.122 and 0.123 add only gated research probes for kerning writes; `set_kerning` needs 0.124 / 0.44, its whole-unit check and panel wording 0.45; open contours are read by server 0.46; listener 0.125 adds only the gated probe `/debug/tryopen`; `draw_path` draws open contours with 0.126 / 0.47; `create_glyph` makes the layer with 0.127 / 0.48; `get_glyph_outline` labels components with 0.128 / 0.49; listener 0.129 adds only the gated probe `/debug/tryshapebox`; a component is checked on its own and against its source with 0.130 / 0.50; listener 0.131 adds only the gated probe `/debug/trynotify`; a glyph write marks the font as changed with 0.132 / 0.51; `save_question_note` follows the mark call alone with server 0.52; a verified delete is marked through a surviving glyph with 0.133 / 0.53; a kerning write that changed an entry is marked with 0.134 / 0.54; its icon note and the reply to a request that changed nothing need server 0.55. What each release changed: [CHANGELOG.md](CHANGELOG.md).
