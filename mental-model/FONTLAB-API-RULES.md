## 10. Hard rules

- **Container access on a native FontLab / fontgate object is forbidden until proven, per object and per call form** (2026-11-03, [archive/DECISIONS-ARCHIVE.md](archive/DECISIONS-ARCHIVE.md)). This means `[]`, `.get()`, `.keys()`, `.values()`, `.items()`, `.has_key()` and iteration. A wrong call is a native crash that `try/except` cannot catch (`layer[0]` and `font.shapes.get/[]/keys()` crashed FontLab, section 9). Allowed are only the rows of the table below, and the real Python containers that FontLab returns (a `list` or `tuple`, such as `layer.shapes` or `layer.getContours()`, and a `dict` checked with `type(x) is dict`): those may be indexed and iterated. `len()` and zero-argument getters have been reliable. Range-check `getNodeAt(i)` against `nodesCount`.
- **How a call is proven** (each step its own request; drop the call at the first failure):
  1. **Names only:** the object's type, `len` and the call's docstring (`/debug/fontdir`, `/debug/classdir`, `/debug/moddir`); nothing is called.
  2. **A gated probe:** `go=yes`, exactly one font open, a per-run cap counted BEFORE the call, the call made once per request, the result's type checked before it is used, and `len` read before and after (`side_effect_detected`).
  3. **A live run in FontLab:** no crash, no side effect, and the numbers compared with FontLab's own display where one exists.
  4. **Then a row in the table**, with its test numbers. A row covers only that object, that argument form and what was seen (FontLab version, font, table state). Another object or form starts again at step 1.
- **Using a proven call:** a product route may use only a call from the table. It needs no `go=yes`, but its stub tests must include a spy that aborts on any other member, a subscript or an iteration of the fake native object, plus a static scan of the route's source.
- **Reporting:** a probe reply names the call it made (`call`, `calls_so_far`, `max_calls`) and its side-effect check. A call that failed is an `error` in the reply, never an empty, missing or zero result. A call that has only passed the stub tests is "stub-tested only", never "proven".
- **Modern API first** (2026-11-04, [DECISIONS.md](DECISIONS.md)): a product route uses a legacy call only where the modern one is missing or proven worse. Each legacy call in product use gets a row in the table "Legacy calls in product use" below, with that reason and its test numbers, or "not yet reviewed".

- Probe unknown objects in stages: names only (`dir`) -> read named attributes -> call whitelisted getters. Never call setters,
  `transform`/`scale`/`translate`, `remove`, `release`, `clone`, `apply*`. One question per probe. `/debug/walk` enforces this.
- **Warm-up:** touch `glyph.layer`, then read `bodyLayer` (otherwise `None` intermittently). **On a Power Brush glyph this warm-up arms F1**, and so does reading `glyph.layers` (`glyph.width` and `glyph.components` were seen not to, 486–496): the next `font.update()` writes a flattened copy of the glyph ([topics/fonts-and-sync.md](topics/fonts-and-sync.md) §8l); read such a glyph from the modern layer.
- **`flLayer.boundingBox` is a property, not a method:** calling it raised "'QRectF' object is not callable" (test 519), although its docstring says `QRectF boundingBox()`; reading it without a call is untested. **`flLayer.inkBox()`**, called with no argument, returned a QRectF equal to the exact ink box with the element transform applied (519–530: cubic, quadratic, slant, scale and offset, Power Brush), with no F1 after it (531–532); Qt names its sides y-down, so `top` is the lower y in font units. Product use since listener 0.121: once per modern-only outline read, read through its zero-argument getters only ([topics/reading.md](topics/reading.md) §8p). The argument form `inkBox(QTransform)` is unproven.
- Reversible value writes are not gated; destructive operations are; anything that changes UI state or constructs objects needs `go=yes`.
- When introspection contradicts itself (attribute sometimes `None`, sometimes populated), suspect FontLab's API before the code.
- Live tests that create glyphs go on the disposable test font; creating a glyph with a name FontLab alters leaves a glyph that may be nameless and undeletable by our tools: only the refusal in the server prevents it.
- **Never use the legacy margin setters** (section 9). Margin and width WRITES go through the modern `flGlyph` only, after the layer exists.
- **A drawing or write is reported successful only after a re-read agrees**; detached objects are built and checked first, the attaching call is last. For curves the re-read is node by node (`nodes_match`), not counts.
- **Never call `findLayerCreate` (or any create) before asking read-only whether the layer already exists** (section 8h). The legacy view LAGS after API writes: "legacy says empty" proves nothing about a glyph drawn through the API.
- Curve building order is part of the recipe: curve conversion descending, smooth flags before handles, handles last (section 8g).

- **Never call the legacy `font.update()` / `glyph.update()` while a glyph that was drawn or changed through the modern API may be unsynced (v9, section 8l).** New code that needs a display refresh goes through `_guard_decide(font)`; a tool that registers modern changes calls `_guard_mark` / `_guard_register`. Never use `flPackage.update()` / `flWorkspace.update()` as a cure (useless).
- **"A font is open" means `CountFonts() >= 1`, not `CurrentFont() is not None`** (placeholder `fgFont`, section 8k). `flPackage()` creates a font immediately: only in gated probes, once per listener run, never as a side effect. **Exception (2026-11-12, [DECISIONS.md](DECISIONS.md)):** `POST /font/create` (`create_font`, listener 0.146) makes ONE `flPackage()` per request, with no per-run cap and with other fonts open, and names or marks the font only after `CountFonts()` rose by one and the current package `isEqual` the new one.
- **Check file identity before editing (v8):** at the start of any turn that patches files, compare the working copies with the last commit (`git status` / `git diff`); if they differ without an explanation, say so, diff against the committed version, review, test and mutation-test before adopting (provenance incident: [LESSONS.md](LESSONS.md)).
- **Do not read whole outlines of big glyphs:** the reply costs about 65 tokens per node. Above about 150 nodes use the draw reply (`nodes_match`, margins) and `get_glyph_sidebearings`, or ask for a summary mode (section 14 P2).
- **Never trust `verified` on the legacy route without `modern_margins_check`:** it is the only protection against a stale legacy view (section 8i).
- **Sync rule (v10):** after a modern write a glyph is synced with `fontlab.Update(<modern glyph wrapper>)` ONLY (`_auto_sync` through `_guard_mark`); one glyph, one call, never without an argument, never `UpdateAll()`, never the assign family (`assignFgLayer`, `assignFontGateData`) or `replaceGlyph` (legacy-to-modern direction, suspected cause of the data loss). A new tool that writes through the modern API must call `_guard_mark` (it then syncs and reports `fontlab_sync` by itself). A glyph counts as synced only after `_guard_classify` says so, never because the call returned.
- **Reading rule (v10):** trust `modern_check.margins_agree`: when it is false the listener already supplies `modern_outline` and the server answers from the modern layer; never answer from a legacy view that disagrees with the modern layer.

- **Kerning rules (v11):** (1) **Never read the whole kerning table or the whole font to answer a kerning question**: ask for the few pairs the task needs (`get_kerning`). (2) A kerning object is read only with its calls in the table of proven calls above, once per pair or request. Since listener 0.104 the product route reads only `flPackage.kerning(current master)` with explicit keys, never the legacy `font.kerning` (rule 7). Never `asDict`, `getPlainPairs`, `items`, `keys`; `set` only in `/kerning/set` (listener 0.124: the `flags` form, one call per pair) and the gated research probe `/debug/trysetkern` (rows in the table above); no `remove`, `clear`, `addGroup`, `deleteGroup`, `renameGroup`, `setPlainPairs`, `scale`; `values()` only on the groups, in research (spy fakes in the tests abort on each of them). (3) A pair that could not be read is an **error, never a zero**; only `None` from FontLab means "no entry" (value 0, `kerned false`). (4) More than 250 pairs in one call needs the person's approval; an agent NEVER sets `confirmed_large_read=true` on its own. (5) Our code never computes a kerning value. It asks the table with explicit keys in FontLab's proven order (glyph : glyph, glyph : class, class : glyph, class : class; [topics/kerning.md](topics/kerning.md) §9.9) and reports which entry answered (`source`). Class names come from FontLab (`getAllGroups()`), never from the caller: group names are not accepted as input. (6) Kerning values are in font units; always report `units_per_em` with them; feature-based, contextual and multi-master kerning are not covered and the agent must say so when it matters. (7) (2026-11-01) Kerning made in FontLab's GUI lives in `flPackage.kerning(<master name>)`; the legacy `font.kerning` can be EMPTY while FontLab applies kerning (defect A, [topics/kerning.md](topics/kerning.md) §9): an empty legacy table proves nothing about the font. (8) `get((a, b))` with a name that is ALSO a class name resolves the class: an exception on that glyph is missed (defect B). FontLab names a class after its first member, so this is common; live tests use class names that cannot collide with glyph names. (9) `get(((name, isGroup), (name, isGroup)))` says per side whether a name is a group: False / False reads ONLY the exact glyph : glyph entry, unambiguous but without class resolution (`None` for a class member, test 188) ([topics/kerning.md](topics/kerning.md) §9.6).

- **Feature code rules (2026-11-03, K11):** `font.features` is read only with its calls in the table of proven calls above, through the gated `/debug/features`. `keys()` is used only when it returns a real list or tuple of text. **Never call `clear`, `remove`, `set_feature` or `set_prefix`** (they change the font); `get_prefix` is not called either (unproven). The feature text is never returned whole (token rule): only its size, line counts, a 300-character head, or the lines naming 1–3 names ([topics/kerning.md](topics/kerning.md) §11).

## 9. Dead ends: do not retry without a genuinely new idea

- `glyph.box` / `glyph.fbox`: always zero. `font.shapes`: `len()` safe, always 0. `glyph.draw(pen)`: zero operations even with
  the warm-up (`getPen()` untried, probably write-only).
- `layer[0]` and `font.shapes.get/[]/keys()` **crashed FontLab**.
- `layer.matrix` (identity), `layer.reference` (0,0), `node.point` (duplicate of x/y), `layer.getProperties()` (empty): none holds
  the element transform.
- `fontlab.CurrentGlyph()` returns the LEGACY `fgGlyph`; the module has no `fl` attribute; `layer.getShapes()` raises "Unexpected
  SeqBase<T> length"; `getActiveShape()` depends on the editor selection.
- `SetCurrentGlyph(glyph)` moves the Glyph panel's "current glyph" but not the editor's, leaving the UI split.
- Theories that proved wrong: that Contour > Convert caused an element offset (an element transform set separately did); that
  `.notdef`'s `bodyLayer` merely needs a warm-up or retry; that falling back to the `strict`/`glayer` routes is a safe way to read an
  unreachable layer (it would report real glyphs as empty); **that FontLab does not map `uniXXXX` names** (section 8: the codepoint was already held); that clearing a codepoint with 0 fails
  (it works; our check was wrong); **that `draw_*` refuses a glyph that already has an outline** (v0.81 replaced it, section 8h) and **that FontLab pairs the handles of a smooth node** (v0.80 stub assumed it; live T3b: no).
- **Legacy margin setters** (`glyph.leftMargin = N`, same for right): CRASHED FontLab on a glyph with an API-built shape. Never again. **Legacy width write** (`glyph.width = N` + `glyph.update()`) loses work on glyphs with shapes.
- **Drawing through `glyph.getPen()`** writes into a stray "Body" layer the editor does not draw (v0.52 result). `shape.addContour` on a detached `flShape`, `flShape(flShapeData)`, `flShape(contour)`, `flContour([flNode...], True)`, `flContour(points, On, True)`: all refused (section 8d, 8e).
- **`font.master.name`** is an empty string (cannot supply the layer name). **GUI refresh calls** listed in section 8f: useless; do not retry.
- **Curve building dead ends (live):** `flContour.insert(i, flNode(x, y, "curve"))` -> "QPointF expected"; relying on FontLab to pair handles of a smooth node (it never moves the partner on assignment); `setPoint` and the `flContour(points)` constructor for fractional coordinates (they ROUND); calling `findLayerCreate` on a glyph whose layer may already exist (it hands back an empty layer; section 8h); `convertToCurve(True)` as a drawing route (auto-placed handles, both ends marked smooth).
- Theories that proved wrong (new): that `updateActiveViewport` removes the ghost fill (it does not); that a GUI that "did not change" means an API write failed (the editor numbers are cached per tab).

- **Stale-legacy-view dead ends (v8):** waiting (7 minutes, no GUI action) does not refresh the legacy view; a plain click on the grid tab and back did not either (it was believed to in v0.25's note; corrected in v0.26). Theory that proved wrong: "the legacy view is stale only for a moment after a write".
- **Unsynced-layer dead ends (v9):** `flPackage.update()` and `flWorkspace.instance().update()` do NOT sync (they return True and change nothing); the legacy `font.update()` / `glyph.update()` after a modern write destroys the layer (section 8l); pre-creating glyphs does not protect; theories that proved wrong: "only the first / only layer is lost" (two were lost), "the GUI step itself syncs" (the next API request does, after a GUI event), "`flWorkspace.addPackage` is needed to register a new font" (`flPackage()` registers it alone), "the layer name of the first glyph can be found from another glyph" (a new font has none: package master fallback).
- **Layer guard's own path:** reading other glyphs (building their wrappers) and a full editor round trip did NOT reproduce the state "wrapper without active layer although the layer exists"; opening the glyph in the editor actually makes the legacy view see the nodes, so the check refuses earlier ("layer not KNOWN to be empty"). Do not spend more live time on it; the stub test stays the evidence.

- **v10 dead ends / corrected theories:** `flGlyph.fillFgData(False, False)` does NOT sync (140a); `updatedFgGlyphs()` is not a "needs sync" signal; "nothing can sync a glyph without a GUI event" (v9) is WRONG: `fontlab.Update(<flGlyph>)` does; theory that the modern and legacy margins might live in different coordinate spaces on a transformed glyph: refuted for scale / offset and skew (143); the probe verdict `lost` for a glyph that never had a layer is a wording artefact (no layer yet), not a loss. NEVER try `Update()` without an argument or `UpdateAll()` as a cure (they update all changed objects; untested and unnecessary).

- **v11 dead ends / corrected theories (kerning, section 8p):** `font.groups.getCompiled()` is NOT a source of kerning groups (first and second members glued, kerning groups mixed with OpenType classes, no side information, 132 groups against 72 in `font.kerning.groups`): do not parse it. `glyph.kerningLeft` / `kerningRight` are not pair values (`o` has `kerningRight` 84 while `T:o` is -227): they are the ids of the glyph's kerning groups as left / right member of a pair, 0 = none (corrected 2026-11-01, tests 200–201, [topics/kerning.md](topics/kerning.md) §9.9). `flPackage.getAllGroups()` and `values()` on the master's `kerning.groups` were called live without harm (tests 198, 199) and return real Python lists. The theory that "group kerning must be resolved by our code" is WRONG: `font.kerning.get((a, b))` resolves classes itself. The theory that an accented glyph inherits its base glyph's direct pairs is NOT supported by `get` (`Aacute:V` gave None while `A:V` is -152). `/debug/fldir` finds no kerning module functions. The FontLab Python documentation site is not reachable from the sandbox (allowlist); do not try to get around it. NEVER call `kerning.asDict`, `getPlainPairs`, `getPlainPairsDict`, `items`, `keys`, `values` (they read the whole table: against the user's standing rule) and never any setter of the kerning object.
- **Kerning dead end (2026-11-01, test 170):** switching to the font window tab does not bring GUI-made kerning into the legacy `font.kerning`; read `flPackage.kerning(master)` instead. **`fontgate.fgKerningObjectPair` as a `get` argument** is refused with a `TypeError` (test 183); use the (name, isGroup) tuples of rule (9).

- **An object `id` passed to an `flItems` call that takes a `uint`** (731, 732, listener 0.134): `id` of an `flPackage` or `flGlyph` is a 13-digit object id, and the call raises `SystemError`. Pass `fgId` (package) or `fgGlyphId` (glyph); the same call with `fgId` ran clean (738), and the probe now refuses a number that does not fit.

- **`fontlab.Update(<flGlyph>)` on a composite** does not bring it back in step with a source moved through a tool (642, one run, Ü the control). A real edit of the source in FontLab did, all four times ([topics/reading.md](topics/reading.md)).

- **Add Component crash (2026-11-09, FontLab 8.9.5, listener 0.126; 612–619, [LIVE-TESTS.md](LIVE-TESTS.md)):** Glyph > Add Component on a glyph made by `create_glyph` (`font.createGlyph`) in a font that already has a component: FontLab crashes a few seconds after OK (Windows `c0000005`, `FontLab 8.exe`, offset `0xf5361d`, five times).
