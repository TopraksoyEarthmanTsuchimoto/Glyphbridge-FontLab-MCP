## 2. What the server offers (v0.31)

Tools: `fontlab_status`, `get_current_font`, `list_glyphs`, **`get_glyph_outline`**, **`check_notdef`**, `create_glyph`,
`delete_glyph`, `get_glyph_width`, `set_glyph_width`, **`get_glyph_sidebearings`**, **`set_glyph_sidebearings`**, **`draw_polygon`**, **`draw_path`** (v0.23; open contours since v0.47 with listener 0.126), `check_glyph_unicode`, `set_glyph_unicode`, **`finish_changes`** (v0.18), **`get_kerning`** (v0.30 / v0.31, section 8p), **`set_kerning`** (v0.44). The bold geometry tools are described in sections 8b to 8d, 8g to 8h and 8p.
Tool names as Claude sees them: [CLAUDE.md](../../CLAUDE.md). After a server update the tool DESCRIPTIONS Claude sees can stay stale even after Claude Desktop was restarted (the behaviour is new, the text is old); a second full restart of Claude Desktop refreshes them.

- **Guard fields (server v0.27):** the write tools (`create_glyph`, `delete_glyph`, `set_glyph_unicode`, `set_glyph_width`, `set_glyph_sidebearings`, `draw_polygon`, `draw_path`) forward ONLY these listener fields, type-checked (wrong types are dropped, a broken reply never raises): `synced_with_fontlab` (bool), `durability_note`, `display_refresh`, `display_refresh_note` (text), `display_refresh_skipped_to_protect`, `display_refresh_unreadable_glyphs`, `layers_missing_since_drawn` (non-empty lists of names). They add short sentences to `agent_instruction` (unsynced change / refresh skipped / layers already lost; each says to tell the person) and never replace the existing text or the save reminder. An older listener sends none of them. Failed calls still raise their ToolError as before (the fields are not shown on errors). Tests: part 16 of `create_unicode_tests.py`.
- **`fontlab_sync` (server v0.29, listener 0.89):** the same write tools (`set_glyph_width`, `set_glyph_sidebearings`, `draw_polygon`, `draw_path`) also forward the listener's `fontlab_sync` block (`attempted`, `synced` bools; `verdict`, `call_error`, `reason` non-empty texts; anything else dropped, a non-dict ignored). A synced write adds no sentence to `agent_instruction`; after an ATTEMPTED but failed sync one extra sentence precedes the old unsynced advice. Tests: part 18 of `create_unicode_tests.py`. Details: section 8m.
- **`get_kerning`** (server v0.30, v0.31; since v0.33 it needs listener 0.104, [topics/kerning.md](kerning.md) §10; section 8p): `get_kerning(pairs=None, text=None, confirmed_large_read=None)`: FontLab's own kerning values from the current master's table (font units, class kerning included, negative = closer; each result names its `source` and the class that answered; the reply names the `master` and, since server 0.37, `fonts_open`, `matched_by` and `family_name`; with several fonts open it reads the font in front, matched by path, and the instruction names it) for selected glyph pairs or for the neighbouring characters of a short text. Never the whole table. Up to 250 pairs at once; more needs the PERSON's approval, and only then may the agent repeat the call with `confirmed_large_read=true` (the refusal message says so). A pair that could not be read answers an `error`, never 0; a pair FontLab has no entry for answers `value 0, kerned false`. Pure read (no change counters, no save). Not covered: other masters, feature-based and contextual kerning (said in every reply). Timeout `5 + pairs/50` s (v0.33). Tests: part 19 of `create_unicode_tests.py`.
- **`set_kerning`** (server v0.44 / v0.45, needs listener 0.124; [topics/kerning.md](kerning.md) §14): `set_kerning(pairs, confirmed_large_write=None)`, `pairs` a list of `[left, right, value]` glyph names and whole font units (a fraction is refused, v0.45). Writes glyph : glyph entries in the current master's table of the font in front, each verified by re-reading; the reply gives `matched_by` (v0.45), `before` / `after` (value and source), `changed`, `exception_over_class`, `set_count`, the table size before and after, and `font_modified`. Names and values are checked before anything is sent; more than 250 pairs need the PERSON's approval (`confirmed_large_write=true`). A pair not confirmed stops the request with an error naming the pairs that were set and, when it changed, what its entry now holds, counted as a change (or an uncertain one). The instruction tells the agent to say that the KERNING panel shows such pairs and values only after a switch to another font and back or a save and reopen, that closing asks no save question and loses them, and that Undo cannot take them back. Timeout `5 + pairs/25` s. Tests: part 27 of `create_unicode_tests.py`.
- **The font of every reply** (listener 0.113 / server 0.38, live 269–272): the listener remembers the font a request used (`_open_font()`, the kerning route) and sends `X-Glyphbridge-Font` (family and style, percent-encoded, joined by `/`), `X-Glyphbridge-Font-Key` (the first 12 hex digits of the SHA-1 of the path, `none` for an empty path) and `X-Glyphbridge-Fonts-Open`; `/health`, `/version`, the probes and requests that used no font get none. Every tool returns through `_with_font`, which adds `font` and `fonts_open`; `font_note` when several fonts are open, the font has no path, or the font changed; `font_changed` (from / to) against the previous tool call of this server process, decided by the path hashes when both exist, otherwise by the names; `font_changed_during_call`, and on a write `change_target_uncertain`, when the parts of one call saw different fonts. A refusal still updates the remembered font, and since server 0.39 its error message ends with the same `font_note` (live 282–284); an older listener adds nothing. Tests: listener 1510–1519c, server part 22.
- Timeouts: `TIMEOUT_SECONDS = 5.0`; `delete_glyph` and the `.notdef` dialog wait up to 120 s for a human click (a 90 s wait of the `.notdef` dialog was confirmed
  live through Claude Desktop; see section 7).
- A timeout raises the "listener did not answer" error. Its wording: a Glyphbridge dialog (the `.notdef` notice or a delete confirmation) may be
  waiting in FontLab, so answer or close it; or FontLab is busy or frozen; and for a requested change, check the font's state before repeating it.
  While a dialog is open the listener serves nothing else, so every other tool call times out after 5 s (live-verified with `/health`).
- **`fontlab_status`** (v0.17): `listener_reachable`, `font_open`, `server_version`, `listener_version` (from the listener's existing `GET /version`; `unknown` when it is
  missing, blank, not text or the call fails), font name/path, and a `compatibility_note` when the listener is older than `MIN_LISTENER_VERSION` (0.82 since server v0.24). The
  version constants must equal the file headers (a test checks it).
- **`create_glyph`** (section 8): refuses unsafe names BEFORE FontLab is called; reports `unicode`, `unicode_status` (`assigned` / `none` / `unreadable` / `unknown`),
  `unicode_assigned_by_fontlab`, `unicode_matches_standard`, `also_held_by` + `glyphs_scanned` (when FontLab assigned none to a name that states a codepoint), `name_warnings`
  (hints only) and an `agent_instruction`.
- **`check_glyph_unicode`**: judges names that state their own codepoint: a single character, `uniXXXX` (exactly 4 UPPERCASE hex digits), `uXXXX`..`uXXXXXX` (no surrogates, at most
  10FFFF). Other multi-character names (the Adobe Glyph List is NOT embedded) say "can't determine" on purpose.
- **`set_glyph_unicode`**: reports `unicode_before/after`, `changed` (+ a note when nothing changed), `also_held_by`, `glyphs_scanned`, and a `duplicate_warning` (warning only: nothing is blocked
  or undone) when another glyph already holds the codepoint; pass **0 to remove** a codepoint. Its docstring tells agents not to call it right after `create_glyph` unless the reply shows
  `none` / `unreadable` and the person wants a codepoint, and never to guess one for a non-standard name.
- Switches: `GLYPHBRIDGE_MODERN=0` (server) or `&modern=no` (listener request) disables the modern-API transform read and falls back to
  an estimate. `GLYPHBRIDGE_NOTDEF_WARN=0` disables the two AUTOMATIC `.notdef` checks (section 7); the `check_notdef` tool still works.
  `GLYPHBRIDGE_PORT` (default 8765) changes only the port the SERVER contacts: the listener's `PORT` constant must be changed to match.
- Self-check without Claude (project folder, listener running): `.\venv\Scripts\python.exe glyphbridge_mcp_server.py --check`
  (read-only; includes a read-only `.notdef` status and the versions), `--check --outline NAME`, `--check --notdef-warn` (**may show the dialog**),
  `--check --with-write-test` (create/delete/width round trip on TEST glyphs; FontLab asks you to confirm the deletions).
- Design decision: width and Unicode writes are not confirmation-gated (reversible); delete **is** (Yes/No dialog).
- **SAVE POLICY (v0.18, decided by the user):** NO Glyphbridge tool ever saves the font (the `.vfc` file); saving is the person's duty (File menu or Ctrl+S). Agents tell the person so,
  **once per task package**, never per step and never in a FontLab dialog. Mechanism: every write reply carries `font_modified` (true only when the font REALLY changed: a created or deleted glyph, a width or
  codepoint that differs afterwards; a refusal, an error or a repeated identical write is false or absent) plus an `agent_instruction`; a write whose outcome is unknown (timeout, HTTP error, unusable
  reply) counts as an UNCERTAIN change; a create that produced a glyph under another name counts as a change; a refused connection counts as nothing. When the whole package is done the agent calls
  **`finish_changes`** ONCE: it returns `save_reminder` (constant `SAVE_REMINDER`: bold markdown, "**You must save if you want to keep these changes: use the File menu or press Ctrl+S in FontLab.**"; since server 0.40 the shortcut is `SAVE_SHORTCUT`, read from the system at startup: Cmd+S on macOS, Ctrl+S otherwise, also in the `save_note` and the tool descriptions, which `_tool()` fills in) to be shown in the
  chat after the agent's summary, and resets the package counters; with no change it returns `save_reminder: null`. `fontlab_status` adds `glyphbridge_changes_this_session`,
  `glyphbridge_uncertain_changes_this_session` and a `save_note` once something changed: they count changes made through THIS server process since it started (not per font; the server cannot see whether the
  person saved, so the numbers never claim the font is unsaved). The listener is unchanged. A test (part 8 of `create_unicode_tests.py`) guards the policy: a spy font whose save-like members
  record any call, plus a static scan of both scripts for `.save(`, `.export...(` and `.generate...(`; both were mutation-tested (a planted save call is caught). Only a live run through Claude Desktop shows
  whether the agent really says it once (section 13, item 9).
  **No save question from FontLab (live 2026-11-03, S1, tests 460–472, [LIVE-TESTS.md](../LIVE-TESTS.md)):** when a font was changed only through the tools (a create, a Unicode
  change, a width change), FontLab closed it, or quit, without asking whether to save; after the person's own Font > New Glyph it asked "Save changes to … before closing?" (470).
  So a person who closes FontLab after an agent's changes loses them without a warning from FontLab; the chat reminder is the only one. Why, and whether drawings, sidebearings
  and deletes behave the same: [WATCH-POINTS.md](../WATCH-POINTS.md).

## 3. Listener endpoints (v0.95)

`/health`, `/version` (`{"version":"0.95"}`); `/font/current` (since listener 0.118 also `package_names` from the font package, or `package_names_unavailable` with the reason; [fonts-and-sync.md](fonts-and-sync.md)); `/font/glyphs`; `/font/nonempty` (layerless glyphs such as an empty
`.notdef` land in `unreadable`, while `/font/notdef` and `/glyph/outline` call the same glyph empty: a known inconsistency, backlog item 11); GET/POST `/glyph/width` and `/glyph/unicode` (POST sets, then re-reads to verify); POST
`/glyph/create` (verified by list re-read); POST `/glyph/delete` (**requires a Yes/No QMessageBox**, default No; since listener 0.114 its text names the client the request named, or none, and the font: family and style, file name or "not saved to a file yet", and "1 of N open fonts" when several are open); GET `/glyph/nodes`
(older, superseded); GET `/shutdown` (stops the listener, not FontLab).

- **Kerning endpoints (listener 0.94 / 0.95; section 8p):** `GET /kerning/pairs?pairs=A:V,T:o` or `?text=AVATAR` (no pair cap since 0.95) and `POST /kerning/pairs` with `{"pairs": [["A","V"],["T","o"]]}` or `{"text": "..."}` (for large reads; body read up to 1,000,000 bytes). Read-only, not gated; reply `open`, `mode`, `master`, `master_count` (v0.104), `units_per_em`, `count`, `errors`, `table_size`, `side_effect_detected`, `results` (each with `source` and, when a class answered, `left_class` / `right_class`); HTTP 400 for bad input. Since 0.104 it reads `flPackage.kerning(current master)` with explicit keys; with several fonts open (0.112) only when the current package's `path` equals the current font's path, otherwise it refuses with the reason; the reply also carries `fonts_open`, `matched_by`, `family_name` (0.112).
- **Kerning write (listener 0.124):** `POST /kerning/set` with `{"pairs": [[left, right, value], ...]}` and nothing else. Not gated (a reversible value write, like width). All checks before the first write; per pair `set(((left, False), (right, False)), float(value))` once, the exact entry and the effective value read before and after; stops at the first pair not confirmed. Reply `open`, `fonts_open`, `matched_by`, `family_name`, `master`, `master_count`, `units_per_em` (the package's), `count`, `set_count`, `stopped`, `table_size_before`, `table_size_after`, `table_size_as_expected`, `results` (`requested`, `before`, `after`, `status` set / failed / not attempted, `set`, `changed`, `exception_over_class`, `reason`, `call_error`); `{"open": true, "error"}` when refused, HTTP 400 for bad input. One activity-log line per request.

- **Geometry endpoints (v0.68 and later):** POST `/glyph/width` (modern route), POST `/glyph/sidebearings` and GET `/glyph/sidebearings?name=X`, POST `/glyph/polygon` (body `{name, points}` OR `{name, contours}`), POST **`/glyph/path`** (v0.81, body `{name, contours}` with point objects, section 8g), GET `/glyph/outline` (adds `modern_check` and `modern_outline`). Section 8b to 8d.

- **POST `/glyph/create`** body `{"name": ..., "scan_unicode": N (optional)}`: when created, the reply carries `unicode` and `unicode_status` (`assigned` = FontLab mapped the name itself, because the
  script never sets a codepoint at creation; `none`; `unreadable` + `unicode_error`), and, if the status is `none` and `scan_unicode` is a plain integer 1..10FFFF, `duplicate_check`
  (`scanned`, `also_held_by`, `unreadable`, or `scan_error`). If NOT created but a glyph appeared under another name, `created_under_other_names` lists the new names (a multiset difference, so a
  second nameless glyph is seen too; it may contain `""`). Since listener 0.127 a created glyph also carries `layer_created` and `layer_name_source`, or `layer_note` when it has no layer ([names-unicode.md](names-unicode.md)).
- **POST `/glyph/unicode`** body `{"name", "unicode"}`: success means the re-read equals the request, **or the request was 0 and the re-read is none**. On success with a non-zero codepoint the reply
  carries `duplicate_check` (a read-only scan of the OTHER glyphs' primary `glyph.unicode`; unreadable glyphs are counted, a failed scan is reported; secondary codepoints are not looked at).
- **GET `/glyph/outline`** `?name=X`, optional `&layer=body|active|strict|glayer`, `&modern=no`: contours (`kind`, `smooth`, `x`, `y`),
  `fontlab_bbox`, `margins`, `component_count`, `shape_count`, `layer_name`, `elements` (true transforms). A zero-layer glyph answers
  `node_count` 0 with `layer_count` 0; a layer that cannot be reached although layers exist gives `layer_unreachable: true` + error.
  Since listener 0.120 a glyph with modern nodes is answered from the modern layer (`source: "modern"`, `modern_outline`, `elements`),
  with `fontlab_ink_box` since 0.121 ([reading.md](reading.md) §8p). Since 0.128 a component's entry in `elements.shapes` also carries `component_glyph` and `component_layer`, or `component_error`; the server turns them into labels and a note ([reading.md](reading.md)).
- **GET `/font/notdef`**: read-only `.notdef` check. **POST `/font/notdef/warn`**: re-checks, then shows the dialog if warranted
  (`{"force": true}` shows it again). Section 7.
- **New gated probes (v0.83 to v0.86; all need `go=yes`, none ever saves, closes, exports or removes anything; each is tested with a forbidden-member spy and a static scan of its source):**
  - `/debug/tryfont?stage=state|construct|attach[&go=yes]` (v0.83): `state` is read-only (workspace: `CountFonts`, `CurrentFont`, packages, current package; since v0.111 also the current package's `path` and `fileName` and `packages_type`, the type name of `packages()`, which is never iterated; T5). `construct&go=yes` runs `fontlab.flPackage()` ONCE per listener run (a second one is refused: each construction leaves a native reference behind) and REGISTERS a new font (section 8k). `attach` (`flWorkspace.instance().addPackage`, once per run) is NOT needed and was never used live.
  - `/debug/trysync?stage=state|package_update|workspace_update[&go=yes]` (v0.85): calls `flPackage.update()` or `flWorkspace.instance().update()` ONCE on the current package; runs only when `CountFonts()` is exactly 1 (plain int) and the workspace holds exactly one non-null package. Result: both are accepted and change nothing (section 8l).
  - `/debug/trycreate?name=N&how=plain|legacy_update&go=yes` (v0.86): ADDS one glyph (name 1 to 40 characters of `A-Za-z0-9._-`, must not exist); `plain` = `font.createGlyph(N)` only, `legacy_update` = createGlyph then `font.update()` (what `create_glyph` did before v0.87); same one-font gate; reply: names before / after, calls made, errors, `calls_so_far`.
  - `/debug/trymodern?stage=state|call|create&name=N[&how=...][&go=yes]` (v0.88): gated experiment for sync candidates and modern glyph creation; `state` is read-only. Section 8o (record and rules).
  - `/debug/tryrefresh?stage=create&name=N&how=Update_flGlyph|none&go=yes` or `?stage=unicode&name=N&value=V&go=yes` (v0.119, F1): `create` ADDS one glyph and, with `Update_flGlyph`, calls `fontlab.Update` once on the new glyph only; `unicode` sets one glyph's codepoint (1 to 1114111) and calls `fontlab.Update` once on that glyph; never `font.update()` or `glyph.update()`; same one-font gate; each mode once per listener run; reply: calls made, errors, counts or the value before and after, `calls_so_far`. Results: [fonts-and-sync.md](fonts-and-sync.md) §8l.
- **Kerning table probe (v0.97, [topics/kerning.md](kerning.md) §9):** `GET /debug/trypkgkern?a=NAME&b=NAME[&master=NAME]&go=yes` reads one pair from `flPackage.kerning(master)` next to `font.kerning`; one-font gate, 20 requests per listener run. v0.100: `&mode=flags&flags=FF|FT|TF|TT` asks `get(((a, flag), (b, flag)))` (flag = "is group"). v0.103: a side flagged T may name a class; only the name rule is checked for it, and the reply lists it under `class_names_not_checked`.
- **Kerning group probe (v0.103, P0.8 R1):** `GET /debug/trykerngroups?stage=all|modes&contains=a,b,c&go=yes` or `?stage=glyph&name=N&go=yes`. `all`: one `flPackage.getAllGroups()`, only the entries whose group or member names equal a token (at most 20). `modes`: the master's `kerning.groups`, one `values()`, and the seven `fgGroup` members (`name`, `mode`, `isLeft`, `isRight`, `isBoth`, `isFeaGroup`, `id`) of the first and the matching entries, each read as an attribute; a callable is never called. `glyph`: the legacy glyph's `kerningLeft` / `kerningRight`. One-font gate, 10 requests per listener run, `len` of the master's table (and of its groups) before and after.
- **Kerning write probe (v0.122, KW, [kerning.md](kerning.md) §13):** `GET /debug/trysetkern?a=A&b=B&value=N&form=tuple|flags&go=yes`: ONE `set` of one glyph pair on `flPackage.kerning(current master)`, with the exact pair and `len()` read before and after; glyph names that no group carries, `|N|` at most the upm; exactly one font open; 10 per listener run. It CHANGES the font in memory.
- **Kerning panel refresh probe (v0.123, KW, §13):** `GET /debug/trykernrefresh?stage=container|update|changed&go=yes`: ONE `flPackage.kerningContainer()`, then `fontlab.Update(container)` or `container.changed()` once; flags and table size before and after; exactly one font open; 6 per listener run. None of them made the KERNING panel list an API-written pair (553–556).
- **Open contour probe (v0.125, P2.1, [reading.md](reading.md) §8e):** `GET /debug/tryopen?stage=detached|draw&name=ocp…&kind=line|curve&go=yes`: ONE open contour (never closed; `line` the V of 581, `curve` the arch of 583), built detached and read back, or drawn into an empty glyph whose name starts with `ocp` and read back from the layer (`layer_closed`, `drawn`); exactly one font open; 6 per listener run. `draw` CHANGES the font in memory.
- **Feature code probe (v0.107 / v0.108, K11, [kerning.md](kerning.md) §11):** `GET /debug/features?stage=tags|size|shape|lines[&tag=T][&contains=a,b,c]&go=yes`. `tags`: one `font.features.keys()`, the tags and their count. `size`, `shape` and `lines` also call `has_key(T)` (only for a listed tag) and `get_feature(T)` (only when that is True), then return only the size, or the line counts by kind with the first 300 characters, or the lines naming 1–3 names (at most 20 per name, cut at 200 characters). One-font gate, 10 requests per listener run in all stages together, `len(features)` before and after. Never called: `clear`, `remove`, `set_feature`, `set_prefix`, `get_prefix`.
- **Loaded-module probe (v0.98, names only, not gated):** `GET /debug/moddir?contains=a,b` (loaded module names), `?module=M&contains=a,b` (names in M), `?module=M&name=N[&members=…]` (docstrings, as `/debug/classdir`), `?stage=kerntype` (type of `font.kerning`). Never imports, constructs or calls anything.
- **Kerning research probes (v0.90 to v0.93, section 8p; kept as evidence tools):** `GET /debug/fontdir?stage=dir|sub|member[&attr=NAME][&members=a,b,c]` (names only: public names, type, `len`, docstrings of ONE font attribute and at most 8 of its members; never calls anything); since listener 0.115 / 0.116 `stage=memberdir&members=PATH` (one member, or a dotted path of up to 3 steps, one level deeper: type, docstring, public names; no value, no call, no `len`); since 0.117 `stage=keys&members=PATH&go=yes` (GATED: one `keys()` call on the object at the end of the path; text lists only; research N1 in [LIVE-TESTS.md](../LIVE-TESTS.md)); `GET /debug/trykern?a=NAME&b=NAME&go=yes` (one `font.kerning.get((a, b))`, 20 calls per listener run, both names must be glyph names); `GET /debug/trygroups?go=yes[&contains=a,b,c]` (one `font.groups.getCompiled()`, 10 per run, returns only a 500-character head or the matching segments). The product route `/kerning/pairs` does not need them.
- New debug probes since v5 (all gated where they change something): `/debug/trylayer?name=&stage=state|create[&method=findLayerCreate|getLayerByName|addLayer&layer=&ref=&go=yes]`, `/debug/readmodern?name=&stage=layer|contour|node[&index=&node=&via=getNodeAt|at]`, `/debug/classdir?name=&doc=&members=a,b,c` (names + `__doc__` of a class's members, never called), `/debug/trymetrics` (disposable glyph, name starts with `tri`; stages names|read|set|doc|refresh|poke), `/debug/tryshape` (history; variants single|points|nodes|probe|curve|curve2|curve3|curve4|curve5, all detached except the gated `curve3` attach; superseded by `/glyph/path`). Probes (read-only unless stated): `/debug/font`, `glyph`, `layerstats`, `objdir`, `findnode`, `layerbbox`, `walk` (restricted
  modern-API walker, whitelist `_WALK_CALL_OK`), `classdir`, `fldir`, `currentshapes`, `buildglyph` (constructs a wrapper; `go=yes`),

## 4. Activity log in the OUTPUT panel (listener 0.102; client name 0.105 / 0.106; launcher 0.109 / 0.110)

The listener tells the person in FontLab's OUTPUT panel what is done to the font. Decision (fulfilled, archived): [archive/DECISIONS-ARCHIVE.md](../archive/DECISIONS-ARCHIVE.md), 2026-11-01; code: the block above `_handle` in the listener.

- **One timestamped line per change:** create, delete, Unicode, width, sidebearings, polygon and path drawing, a shown `.notdef` dialog, and every `/debug/...` request with `go=yes`. Example: `[local-agent-mode > Glyphbridge] 20:41:49 width ol1A: 0 -> 600 (verified)`.
- **Honest words:** "verified" only where the reply's own re-read says so. Always printed, never collapsed: `REFUSED` (400), `FAILED` (500), "no font is open", `NOT DONE` (with the reply's reason, and "the glyph DID change" when it did), declined deletes, unsynced or warned results, every delete, every gated probe.
- **No flooding:** a run of verified changes of one kind shows 3 lines, then one "N more like this, all verified" line. Reads are counted by kind (kerning with its pair count; `/health`, `/version`, `/shutdown` not at all) and printed as one "reads:" line. Both summaries are printed before a different change, after `_ACTIVITY_IDLE_S` = 10 s without a request (the poll timer checks), and at `/shutdown`. A summary carries the time it is printed, not the time of its reads (test 236: a read at 01:24:31 was printed at 01:24:36, when another client sent a request).
- **Client name (0.105 / 0.106):** the server sends the app's own MCP name (`title`, else `name`) in the `X-Glyphbridge-Client` header of every request; `--check` sends `glyphbridge --check`. The listener shows it percent-decoded, without control characters and without the config entry name `glyphbridge-fontlab`, at most 40 characters. Without one (`curl`, PowerShell, a browser), the line starts with `[Glyphbridge]` since 0.109 (before: `unknown agent`, a guess).
