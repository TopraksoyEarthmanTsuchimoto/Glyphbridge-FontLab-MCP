## 2. What the server offers (v0.31)

Tools: `fontlab_status`, `get_current_font`, `list_glyphs`, **`get_glyph_outline`**, **`check_notdef`**, `create_glyph`,
`delete_glyph`, `get_glyph_width`, `set_glyph_width`, **`get_glyph_sidebearings`**, **`set_glyph_sidebearings`**, **`draw_polygon`**, **`draw_path`** (v0.23; open contours since v0.47 with listener 0.126), `check_glyph_unicode`, `set_glyph_unicode`, **`finish_changes`** (v0.18), **`get_kerning`** (v0.30 / v0.31, section 8p), **`set_kerning`** (v0.44), **`remove_kerning`** (v0.76, listener 0.192: POST `/kerning/remove`, [kerning.md](kerning.md) §16), **`create_font`** (v0.60), **`move_nodes`** (v0.63, listener 0.153: POST `/glyph/move`, [geometry.md](geometry.md) "Editing existing outlines"; since v0.65 with `undo_note` and without `display_note`), **`add_component`** (v0.66, listener 0.169: POST `/glyph/component`, [reading.md](reading.md) "Components: placing one through the API"; live AC 1079–1101), **`remove_component`** (v0.72, listener 0.179: POST `/glyph/component/remove`; live RC 1257–1264b; design: [DECISIONS.md](../DECISIONS.md) 2026-11-18), **`rename_kerning_group`** and **`remove_kerning_group`** (v0.82, listener 0.200: POST `/kerning/group/rename`, `/kerning/group/remove`; [kerning.md](kerning.md) §18; not yet run live). The bold geometry tools are described in sections 8b to 8d, 8g to 8h and 8p.
Tool names as Claude sees them: [CLAUDE.md](../../CLAUDE.md). After a server update the tool DESCRIPTIONS Claude sees can stay stale even after Claude Desktop was restarted (the behaviour is new, the text is old); a second full restart of Claude Desktop refreshes them.

- **Guard fields (server v0.27):** the write tools (`create_glyph`, `delete_glyph`, `set_glyph_unicode`, `set_glyph_width`, `set_glyph_sidebearings`, `draw_polygon`, `draw_path`) forward ONLY these listener fields, type-checked (wrong types are dropped, a broken reply never raises): `synced_with_fontlab` (bool), `durability_note`, `display_refresh`, `display_refresh_note` (text), `display_refresh_skipped_to_protect`, `display_refresh_unreadable_glyphs`, `layers_missing_since_drawn` (non-empty lists of names). They add short sentences to `agent_instruction` (unsynced change / refresh skipped / layers already lost; each says to tell the person) and never replace the existing text or the save reminder. An older listener sends none of them. Failed calls still raise their ToolError as before (the fields are not shown on errors). Tests: part 16 of `create_unicode_tests.py`.
- **`fontlab_sync` (server v0.29, listener 0.89):** the same write tools (`set_glyph_width`, `set_glyph_sidebearings`, `draw_polygon`, `draw_path`) also forward the listener's `fontlab_sync` block (`attempted`, `synced` bools; `verdict`, `call_error`, `reason` non-empty texts; anything else dropped, a non-dict ignored). A synced write adds no sentence to `agent_instruction`; after an ATTEMPTED but failed sync one extra sentence precedes the old unsynced advice. Tests: part 18 of `create_unicode_tests.py`. Details: section 8m.
- **`get_kerning`** (server v0.30, v0.31; since v0.33 it needs listener 0.104, [topics/kerning.md](kerning.md) §10; section 8p): `get_kerning(pairs=None, text=None, confirmed_large_read=None)`: FontLab's own kerning values from the current master's table (font units, class kerning included, negative = closer; each result names its `source` and the class that answered; the reply names the `master` and, since server 0.37, `fonts_open`, `matched_by` and `family_name`; with several fonts open it reads the font in front, matched by path, and the instruction names it) for selected glyph pairs or for the neighbouring characters of a short text. Never the whole table. Up to 250 pairs at once; more needs the PERSON's approval, and only then may the agent repeat the call with `confirmed_large_read=true` (the refusal message says so). A pair that could not be read answers an `error`, never 0; a pair FontLab has no entry for answers `value 0, kerned false`. Pure read (no change counters, no save). Not covered: other masters, feature-based and contextual kerning (said in every reply). Timeout `5 + pairs/50` s (v0.33). Tests: part 19 of `create_unicode_tests.py`.
- **`get_kerning_groups`** (server v0.75, needs listener 0.190; [topics/kerning.md](kerning.md) §15; P1.6): `get_kerning_groups(groups=None, glyphs=None, all_groups=None, confirmed_large_read=None)`: the current master's kerning groups, through `POST /kerning/groups`. Names in `groups` and / or `glyphs`, or `all_groups=true` alone; names are 1–63 characters from `A-Z a-z 0-9 . _ -`, folded when repeated; more than 250 names, or an all-groups read of more than 250 groups, is refused until the person approves (`confirmed_large_read=true`). Each group: `side` (`left`, `right`, `both`, `unknown`), `fontlab_side`, members, `member_count`, `id`, `confirmed` (with `mismatch` and `class_list_members` when false; an `unknown` side is never confirmed); each glyph: its `kerning_groups`, or the note "in no kerning group on either side"; an unknown name is an `error` for that name only. Reply also: `mode`, `group_count`, `cross_check`, `errors`, `unconfirmed`, `member_names`, `large_read_confirmed`, the font fields of `get_kerning`; `agent_instruction` explains the sides, never to pick between two versions, that OpenType classes and Glyph tags are not read, and that other masters are not covered. A pure read: no change count, no `finish_changes`.
- **`set_kerning`** (server v0.44 / v0.45, needs listener 0.124; [topics/kerning.md](kerning.md) §14): `set_kerning(pairs, confirmed_large_write=None)`, `pairs` a list of `[left, right, value]` glyph names and whole font units (a fraction is refused, v0.45). Writes glyph : glyph entries in the current master's table of the font in front, each verified by re-reading; the reply gives `matched_by` (v0.45), `before` / `after` (value and source), `changed`, `exception_over_class`, `set_count`, the table size before and after, and `font_modified`. Names and values are checked before anything is sent; more than 250 pairs need the PERSON's approval (`confirmed_large_write=true`). A pair not confirmed stops the request with an error naming the pairs that were set and, when it changed, what its entry now holds, counted as a change (or an uncertain one). The instruction tells the agent to say that the KERNING panel shows such pairs and values only after a switch to another font and back or a save and reopen, that closing loses them unsaved (with no save question first when no mark was made: a listener older than 0.134, or `save_question_note`), and that Undo cannot take them back. Since server 0.54 / listener 0.134 the reply carries `fontlab_changed_mark`. Since server 0.55 a marked write adds the icon note (point (4), `_ICON_MAY_LAG_KERNING`, [DECISIONS.md](../DECISIONS.md)), and a request that changed nothing says so. Since server 0.56 / listener 0.136 the reply carries `fontlab_panel_refresh`, and point (1) says that FontLab was asked to refresh its KERNING panel when that call was made without error ([kerning.md](kerning.md) §14). Since server 0.57 the icon note is off (`_ICON_MAY_LAG_KERNING = False`, 749–753), and point (1) of a request that changed nothing says the panel was not asked to refresh. Timeout `5 + pairs/25` s. Tests: part 27 of `create_unicode_tests.py`.
- **`create_font`** (server 0.60, needs listener 0.146; ROADMAP P0.3 / P0.4, [fonts-and-sync.md](fonts-and-sync.md) §8k): `create_font(family=None)` makes one new, unsaved font, with or without other fonts open. Without `family` FontLab names it (`Unnamed`, `Unnamed1`, …); with one, the font is named as Build Names would for the style Regular. `family` is checked before anything is sent: printable ASCII, no edge space, none of `[](){}<>/%`, at most 63 characters, and a PostScript name of at most 63 (so at most 55 characters without spaces). The reply gives the five names, `named_by`, `saved: false`, the open-font counts, upm, masters and glyph count, `fontlab_changed_mark`, and with a name `names_set`, `legacy_family_set` and `name_problems`; `person_notes` are the listener's notes, and the instruction tells the agent to relay every one and, with a name, to offer to explain Font Info's Names page; since 0.61 it also tells the agent to point the person to FontLab's OUTPUT panel once per conversation. A font made but not confirmed raises an error that says so and counts as a change; an unknown outcome counts as an uncertain one. Tests: part 36 of `create_unicode_tests.py`. Run live 915–925 (0.146 / 0.60 and 0.147 / 0.61).
- **The font of every reply** (listener 0.113 / server 0.38, live 269–272): the listener remembers the font a request used (`_open_font()`, the kerning route) and sends `X-Glyphbridge-Font` (family and style, percent-encoded, joined by `/`), `X-Glyphbridge-Font-Key` (the first 12 hex digits of the SHA-1 of the path, `none` for an empty path) and `X-Glyphbridge-Fonts-Open`; `/health`, `/version`, the probes and requests that used no font get none. Every tool returns through `_with_font`, which adds `font` and `fonts_open`; `font_note` when several fonts are open, the font has no path, or the font changed; `font_changed` (from / to) against the previous tool call of this server process, decided by the path hashes when both exist, otherwise by the names; `font_changed_during_call`, and on a write `change_target_uncertain`, when the parts of one call saw different fonts. A refusal still updates the remembered font, and since server 0.39 its error message ends with the same `font_note` (live 282–284); an older listener adds nothing. Tests: listener 1510–1519c, server part 22.
- Timeouts: `TIMEOUT_SECONDS = 5.0`. Since server 0.83 / listener 0.203 (2026-11-24, run live SD 1604–1611a): the Yes/No dialogs of `delete_glyph` and
  `remove_kerning_group` close by themselves after `DIALOG_SECONDS` (45, sent as `dialog_seconds`; the listener keeps it within 10–50), counted as
  no answer (`not_answered_in_time`, nothing changed; the agent asks before trying again); the server waits `DIALOG_WAIT_SECONDS` (55); both tools
  refuse an older listener. The `.notdef` notice is no longer a dialog (section 7). Until 0.82 / 0.202 these dialogs and the `.notdef` dialog waited
  up to 120 s (a 90 s wait of the `.notdef` dialog was confirmed live through Claude Desktop).
- A timeout raises the "listener did not answer" error. Its wording (since 0.83): FontLab is probably busy or frozen, since Glyphbridge's own dialogs
  close by themselves within 45 s; and for a requested change, check the font's state before repeating it.
  While a dialog is open the listener serves nothing else, so every other tool call times out after 5 s (live-verified with `/health`).
- **The client's time limit during a dialog (TO 1577–1582 and TO2 1583–1587, 2026-11-21, one run each):** in Claude Desktop's Code tab a Glyphbridge call went to a server instance started by Claude Desktop's main process; the instance Claude Code started from `.mcp.json` ran unused. The Desktop chat reaches this PC through a remote link and gave up after about 80 s (TO2 1585, its own wording; in the chat era it waited 90 s for the `.notdef` dialog, [notdef.md](notdef.md), "Long wait"). It used the same server instance as the Code tab, whose `finish_changes` then counted the chat's timed-out delete as uncertain (1587); that instance was not replaced after the chat's timeout (1586). - **`fontlab_status`** (v0.17): `listener_reachable`, `font_open`, `server_version`, `listener_version` (from the listener's existing `GET /version`; `unknown` when it is
  missing, blank, not text or the call fails), font name/path, and a `compatibility_note` when the listener is older than `MIN_LISTENER_VERSION` (0.82 since server v0.24). The
  version constants must equal the file headers (a test checks it).
- **`create_glyph`** (section 8): refuses unsafe names BEFORE FontLab is called; reports `unicode`, `unicode_status` (`assigned` / `none` / `unreadable` / `unknown`),
  `unicode_assigned_by_fontlab`, `unicode_matches_standard`, `also_held_by` + `glyphs_scanned` (when FontLab assigned none to a name that states a codepoint), `name_warnings`
  (hints only) and an `agent_instruction`.
- **`check_glyph_unicode`**: judges names that state their own codepoint: a single character, `uniXXXX` (exactly 4 UPPERCASE hex digits), `uXXXX`..`uXXXXXX` (no surrogates, at most
  10FFFF). Other multi-character names (the Adobe Glyph List is NOT embedded) say "can't determine" on purpose.
- **`set_glyph_unicode`**: reports `unicode_before/after`, `changed` (+ a note when nothing changed), `also_held_by`, `glyphs_scanned`, and a `duplicate_warning` (warning only: nothing is blocked
  or undone) when another glyph already holds the codepoint; pass **0 to remove** a codepoint. Its docstring tells agents not to call it right after `create_glyph` unless the reply shows
  `none` / `unreadable` and the person wants a codepoint, and never to guess one for a non-standard name.
- Switches: `GLYPHBRIDGE_MODERN=0` (server) or `&modern=no` (listener request) disables the modern-API transform read and falls back to
  an estimate. `GLYPHBRIDGE_NOTDEF_WARN=0` disables the two AUTOMATIC `.notdef` checks (section 7); the `check_notdef` tool still works. A setting for scripts and automation, set as `"env"` in the AI app's config entry; it is not in the user's install guide (DECISIONS 2026-11-24).
  `GLYPHBRIDGE_PORT` (default 8765) changes only the port the SERVER contacts: the listener's `PORT` constant must be changed to match.
- Self-check without Claude (project folder, listener running): `.\venv\Scripts\python.exe glyphbridge_mcp_server.py --check`
  (read-only; includes a read-only `.notdef` status and the versions), `--check --outline NAME`, `--check --notdef-warn` (**may add a line to FontLab's OUTPUT panel**; a dialog until listener 0.202),
  `--check --with-write-test` (create/delete/width round trip on TEST glyphs; FontLab asks you to confirm the deletions).
- Design decision: width and Unicode writes are not confirmation-gated (reversible); delete **is** (Yes/No dialog).
- **SAVE POLICY (v0.18, decided by the user):** NO Glyphbridge tool ever saves the font (the `.vfc` file); saving is the person's duty (File menu or Ctrl+S). Agents tell the person so,
  **once per task package**, never per step and never in a FontLab dialog. Mechanism: every write reply carries `font_modified` (true only when the font REALLY changed: a created or deleted glyph, a width or
  codepoint that differs afterwards; a refusal, an error or a repeated identical write is false or absent) plus an `agent_instruction`; a write whose outcome is unknown (timeout, HTTP error, unusable
  reply) counts as an UNCERTAIN change; a create that produced a glyph under another name counts as a change; a refused connection counts as nothing. When the whole package is done the agent calls
  **`finish_changes`** ONCE: it returns `save_reminder` (constant `SAVE_REMINDER`: bold markdown, "**You must save if you want to keep these changes: use the File menu or press Ctrl+S in FontLab.**"; since server 0.40 the shortcut is `SAVE_SHORTCUT`, read from the system at startup: Cmd+S on macOS, Ctrl+S otherwise, also in the `save_note` and the tool descriptions, which `_tool()` fills in) to be shown in the
  chat after the agent's summary, and resets the package counters; with no change it returns `save_reminder: null`. `fontlab_status` adds `glyphbridge_changes_this_session`,
  `glyphbridge_uncertain_changes_this_session` and a `save_note` once something changed: they count changes made through THIS server process since it started (not per font; the server cannot see whether the
  person saved, so the numbers never claim the font is unsaved). The listener is unchanged. A test (part 8 of `create_unicode_tests.py`) guards the policy: a spy font whose save-like members
  record any call, plus a static scan of both scripts for `.save(`, `.export...(` and `.generate...(`; both were mutation-tested (a planted save call is caught). Only a live run through Claude Desktop shows
  whether the agent really says it once (section 13, item 9).
  **The change log (listener 0.204 / server 0.85, 2026-11-24, run live CL 1618–1634, [LIVE-TESTS.md](../LIVE-TESTS.md); [DECISIONS.md](../DECISIONS.md), 2026-11-24):** both counts
  are kept, and the listener's decides. The listener logs every product write before its reply goes out: verdict yes / no / unknown from
  the route's reply by general rules (`_change_verdict`), the request and server-run IDs, client, kind, target, the font in front (package
  `fgId`) and one sequence number per listener run; the last 1,000 entries are kept, each font's total never trimmed. `POST /changes`
  reads it: entries after the server's bookmark by font and sender, dropped entries, totals, and a verdict per asked request ID.
  `finish_changes` applies the five rules: an unanswered write is asked about; either side's change brings the reminder (higher count
  stands, `counts_disagree`); `change_record` is `complete`, `incomplete` (listener restarted, entries dropped; the server's count is
  used) or `unavailable` (listener older than 0.204); only this server's bookmark moves; `other_changes` (another app, or an earlier
  server process) are named and bring a reminder on their own, "they may already have been saved". `fontlab_status` adds
  `changes_by_font` from the totals without moving the bookmark. Since server 0.86 it always answers (rule 3): `[]` when the
  listener recorded nothing since it started (the note names that start; earlier changes are not known), `"unknown"` with the
  reason when `/changes` fails or its reply holds no readable totals, and the note counts any unreadable entries beside readable ones.

## 3. Listener endpoints (v0.95)

`/health`, `/version` (`{"version":"0.95"}`); `/font/current` (since listener 0.118 also `package_names` from the font package, or `package_names_unavailable` with the reason; [fonts-and-sync.md](fonts-and-sync.md)); `/font/glyphs`; `/font/nonempty` (layerless glyphs such as an empty
`.notdef` land in `unreadable`, while `/font/notdef` and `/glyph/outline` call the same glyph empty: a known inconsistency, backlog item 11); GET/POST `/glyph/width` and `/glyph/unicode` (POST sets, then re-reads to verify; since listener 0.198 GET `/glyph/width` answers with `advanceWidth`, `source` "modern", and the legacy `glyph.width` as `legacy_width`, or, when the modern side cannot be reached, with the legacy width, `source` "legacy" and `modern_reason`; server 0.81 shows `legacy_width` only when the two differ by 0.01 or more); POST
`/glyph/create` (verified by list re-read); POST `/glyph/delete` (**requires a Yes/No QMessageBox**, default No; since listener 0.114 its text names the client the request named, or none, and the font: family and style, file name or "not saved to a file yet", and "1 of N open fonts" when several are open); GET `/glyph/nodes`
(older, superseded); GET `/shutdown` (stops the listener, not FontLab).

- **Kerning endpoints (listener 0.94 / 0.95; section 8p):** `GET /kerning/pairs?pairs=A:V,T:o` or `?text=AVATAR` (no pair cap since 0.95) and `POST /kerning/pairs` with `{"pairs": [["A","V"],["T","o"]]}` or `{"text": "..."}` (for large reads; body read up to 1,000,000 bytes). Read-only, not gated; reply `open`, `mode`, `master`, `master_count` (v0.104), `units_per_em`, `count`, `errors`, `table_size`, `side_effect_detected`, `results` (each with `source` and, when a class answered, `left_class` / `right_class`); HTTP 400 for bad input. Since 0.104 it reads `flPackage.kerning(current master)` with explicit keys; with several fonts open (0.112) only when the current package's `path` equals the current font's path, otherwise it refuses with the reason; the reply also carries `fonts_open`, `matched_by`, `family_name` (0.112).
- **Kerning groups (listener 0.190, P1.6):** `GET /kerning/groups?groups=a,b&glyphs=c,d` or `?all=yes[&confirmed=yes]`, and `POST /kerning/groups` with `{"groups": [...], "glyphs": [...]}` or `{"all_groups": true[, "confirmed_large_read": true]}` and nothing else. ## 4. Activity log in the OUTPUT panel (listener 0.102; client name 0.105 / 0.106; launcher 0.109 / 0.110)

The listener tells the person in FontLab's OUTPUT panel what is done to the font. Decision (fulfilled, archived): [archive/DECISIONS-ARCHIVE.md](../archive/DECISIONS-ARCHIVE.md), 2026-11-01; code: the block above `_handle` in the listener.

- **One timestamped line per change:** create, delete, Unicode, width, sidebearings, polygon and path drawing, a `.notdef` note (a shown `.notdef` dialog until listener 0.202), a dialog not answered in time or not shown (since 0.203), and every `/debug/...` request with `go=yes`. A new font (listener 0.146) gets its line and then one `note:` line for each thing the person must know (cut at 400 characters), so the warnings reach a person who works in FontLab without reading the chat. Example: `[local-agent-mode > Glyphbridge] 20:41:49 width ol1A: 0 -> 600 (verified)`.
- **Honest words:** "verified" only where the reply's own re-read says so. Always printed, never collapsed: `REFUSED` (400), `FAILED` (500), "no font is open", `NOT DONE` (with the reply's reason, and "the glyph DID change" when it did), declined deletes, unsynced or warned results, every delete, every gated probe.
- **No flooding:** a run of verified changes of one kind shows 3 lines, then one "N more like this, all verified" line. Reads are counted by kind (kerning with its pair count; `/health`, `/version`, `/shutdown` not at all) and printed as one "reads:" line. Both summaries are printed before a different change, after `_ACTIVITY_IDLE_S` = 10 s without a request (the poll timer checks), and at `/shutdown`. A summary carries the time it is printed, not the time of its reads (test 236: a read at 01:24:31 was printed at 01:24:36, when another client sent a request).
- **Client name (0.105 / 0.106):** the server sends the app's own MCP name (`title`, else `name`) in the `X-Glyphbridge-Client` header of every request; `--check` sends `glyphbridge --check`. The listener shows it percent-decoded, without control characters and without the config entry name `glyphbridge-fontlab`, at most 40 characters. Without one (`curl`, PowerShell, a browser), the line starts with `[Glyphbridge]` since 0.109 (before: `unknown agent`, a guess). Both Claude apps send `local-agent-mode-glyphbridge-fontlab`, shown as `local-agent-mode` (tests 225, 226, 229). The summaries are printed when the name changes.
- **Launcher (0.109 / server 0.35; one name since 0.110 / 0.36):** the server reads once at startup the file name of the program that started it and sends it in `X-Glyphbridge-Launcher` (`claude.exe`); [CHANGELOG.md](../CHANGELOG.md) has the method and its privacy limits. The listener shows it without `.exe` and in capitals (`CLAUDE`). The first time a client name comes with a new launcher, one line names both: `… from "local-agent-mode" | CLAUDE.` in the "Connected" line for the first pair, else `[glyphbridge] local-agent-mode | CLAUDE`. On this PC the Desktop app starts the servers for both the chat and the Code tab (tests 237–238), so both read `CLAUDE`. Claude Code, which the Desktop app runs for the Code tab and whose program is also named `claude.exe`, starts one more instance from `.mcp.json`; in TO 1580 (2026-11-21) the Code tab's call went to an instance Claude Desktop started, and Claude Code's own stayed unused.
- **No font open (0.105):** a read answered `open: false` is listed as `no font open: <kind> N` in the reads line and adds no kerning pairs; a refused write prints `REFUSED <kind> <name>: no font is open` (test 227).
- **Safety:** built only from the request and the reply, never a `fontlab` call; both entry points swallow their own errors, so logging cannot change or block a reply. ASCII, except a client name with other characters (not seen live).
- **Seen live (236–242; moved from [WATCH-POINTS.md](../WATCH-POINTS.md) on 2026-11-12):** the client name names the app, not the model, and both Claude apps send the same name. The launcher does not tell them apart on this PC either: the Desktop app starts the servers for both (237–238). A name with non-ASCII characters: not seen in FontLab.
- **Switch:** `_ACTIVITY_LOG = "normal"` (changes and reads), `"writes"` (changes only) or `"off"`; a one-line source edit.
- **Limits:** the client name is the app's own claim, not checked; it names the app, not the model, and both Claude apps send the same one. A launcher name is only a file name: not proof of the program, and nothing about the model; two sessions of one kind look the same. No line names a tool (optional: [ROADMAP.md](../ROADMAP.md) P6.2).
