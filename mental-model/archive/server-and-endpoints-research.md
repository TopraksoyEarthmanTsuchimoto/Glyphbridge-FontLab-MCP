## 2. What the server offers (v0.31)

  **The icon and the readings (moved from [WATCH-POINTS.md](../WATCH-POINTS.md) on 2026-11-10):** blue and FontLab asked (469, 470, the fonts of 659, 662, 667), dark and it did not (561, 663). In the research rounds the icon repainted only when the mouse neared the font's title (657–667); after the built marks it turned blue at once, without a hover (668, 669; kerning 748–753). A marked drawing stayed marked after a further `create_glyph` (661, 662, 665–667); without the call the icon stayed dark after a hover and FontLab did not ask (663). Ctrl+S turns the icon dark, which isolates one write without a gated probe: width, sidebearings, `draw_polygon`, `draw_path` and Unicode each turned it blue again alone (677–681). No reading follows the icon: `isChanged` and `hasChanges` read false while it was blue (659); the package's `currentHistoryState` read 1 after a GUI Font > New Glyph (659b) and 0 while blue after the call (661). Undo stayed greyed out after the call (661).

  **`add_component` alone brings the question (live 2026-11-17, 1097–1101, listener 0.170):** with the mark switched off (`/debug/markswitch`) the setup writes of two new fonts were left unmarked; one font then got `add_component` with the mark on and asked "Save changes to … before closing?" (1099); the other, the control without it, closed without a question (1101). One run.
  **Names (live 2026-11-12, 911–914, [fonts-and-sync.md](../topics/fonts-and-sync.md) §8k):** a name written through the API (`flPackage.ffn`) leaves the font unmarked: it closed with no question (911). The same `notifyChangesApplied(title, <flPackage>, False)` as for glyphs, made after the write, turned the icon blue and FontLab asked on close, on a font from File > New Font (912) and on one made by `flPackage()` (913); with two other fonts open, `construct_named&mark=yes` (listener 0.145) marked only the new font (914). One run each; the dialog names the font by its package Full name.

**A glyph's history after the notification (661, 665, 668, 669; moved from [WATCH-POINTS.md](../WATCH-POINTS.md) on 2026-11-12, where the open question stays):** `currentHistoryState` and `initialHistoryState` moved together: 0 → 2 and 0 → 3 in one listener run, 0 → 1 and 0 → 2 in the next, on a new font each time, as if one counter ran across fonts. `hasChanges` read false after the 1 (668), true after the others and on all 20 marks of 670–681, false again on the first mark after a listener start (setup of 688, as in 668), while the icon turned blue every time. In 686 only the current position moved (77 → 79, initial 77).

**The change counter outlives sessions (moved from [WATCH-POINTS.md](../WATCH-POINTS.md) on 2026-11-12, where the entry stays):** `fontlab_status` showed 9, and later 20, changes at the start of Claude Code sessions that had made none (also after a full FontLab restart), 6 at the start of the session of 2026-11-03, and 25 at the start of a later one that day, 1 at the start of the session of 2026-11-04; after a full Claude Desktop restart, no counter. Inferred: the server process outlives the sessions. Not checked in the process list.

## 3. Listener endpoints (v0.95)

- **New gated probes (v0.83 to v0.86; all need `go=yes`, none ever saves, closes, exports or removes anything; each is tested with a forbidden-member spy and a static scan of its source):**
  - `/debug/tryfont?stage=state|construct|attach[&go=yes]` (v0.83): `state` is read-only (workspace: `CountFonts`, `CurrentFont`, packages, current package; since v0.111 also the current package's `path` and `fileName` and `packages_type`, the type name of `packages()`, which is never iterated; T5). `construct&go=yes` runs `fontlab.flPackage()` ONCE per listener run (a second one is refused: each construction leaves a native reference behind) and REGISTERS a new font (section 8k). `attach` (`flWorkspace.instance().addPackage`, once per run) is NOT needed and was never used live.
  - `/debug/trysync?stage=state|package_update|workspace_update[&go=yes]` (v0.85): calls `flPackage.update()` or `flWorkspace.instance().update()` ONCE on the current package; runs only when `CountFonts()` is exactly 1 (plain int) and the workspace holds exactly one non-null package. Result: both are accepted and change nothing (section 8l).
  - `/debug/trycreate?name=N&how=plain|legacy_update&go=yes` (v0.86): ADDS one glyph (name 1 to 40 characters of `A-Za-z0-9._-`, must not exist); `plain` = `font.createGlyph(N)` only, `legacy_update` = createGlyph then `font.update()` (what `create_glyph` did before v0.87); same one-font gate; reply: names before / after, calls made, errors, `calls_so_far`.
  - `/debug/trymodern?stage=state|call|create&name=N[&how=...][&go=yes]` (v0.88): gated experiment for sync candidates and modern glyph creation; `state` is read-only. Section 8o (record and rules).
  - `/debug/tryrefresh?stage=create&name=N&how=Update_flGlyph|none&go=yes` or `?stage=unicode&name=N&value=V&go=yes` (v0.119, F1): `create` ADDS one glyph and, with `Update_flGlyph`, calls `fontlab.Update` once on the new glyph only; `unicode` sets one glyph's codepoint (1 to 1114111) and calls `fontlab.Update` once on that glyph; never `font.update()` or `glyph.update()`; same one-font gate; each mode once per listener run; reply: calls made, errors, counts or the value before and after, `calls_so_far`. Results: [fonts-and-sync.md](../topics/fonts-and-sync.md) §8l.
- **Kerning table probe (v0.97, [topics/kerning.md](../topics/kerning.md) §9):** `GET /debug/trypkgkern?a=NAME&b=NAME[&master=NAME]&go=yes` reads one pair from `flPackage.kerning(master)` next to `font.kerning`; one-font gate, 20 requests per listener run. v0.100: `&mode=flags&flags=FF|FT|TF|TT` asks `get(((a, flag), (b, flag)))` (flag = "is group"). v0.103: a side flagged T may name a class; only the name rule is checked for it, and the reply lists it under `class_names_not_checked`.
- **Kerning group probe (v0.103, P0.8 R1):** `GET /debug/trykerngroups?stage=all|modes&contains=a,b,c&go=yes` or `?stage=glyph&name=N&go=yes`. `all`: one `flPackage.getAllGroups()`, only the entries whose group or member names equal a token (at most 20). `modes`: the master's `kerning.groups`, one `values()`, and the seven `fgGroup` members (`name`, `mode`, `isLeft`, `isRight`, `isBoth`, `isFeaGroup`, `id`) of the first and the matching entries, each read as an attribute; a callable is never called. `glyph`: the legacy glyph's `kerningLeft` / `kerningRight`. One-font gate, 10 requests per listener run, `len` of the master's table (and of its groups) before and after.
- **Kerning write probe (v0.122, KW, [kerning.md](../topics/kerning.md) §13):** `GET /debug/trysetkern?a=A&b=B&value=N&form=tuple|flags&go=yes`: ONE `set` of one glyph pair on `flPackage.kerning(current master)`, with the exact pair and `len()` read before and after; glyph names that no group carries, `|N|` at most the upm; exactly one font open; 10 per listener run. It CHANGES the font in memory. Since v0.193 (CW, [kerning.md](../topics/kerning.md) §17): `&left=glyph|class&right=glyph|class` (default `glyph`); a class side needs `form=flags`, is sent as `(name, True)`, and must be a kerning group confirmed by `items()` and `getAllGroups()` on a side that fits (left or both on the left, right or both on the right); the reply then adds `left`, `right`, `classes` and the groups' `len()` before and after.
- **Kerning remove probe (v0.191, [kerning.md](../topics/kerning.md) §16; class sides since v0.193 as above):** `GET /debug/trydelkern?a=A&b=B&form=tuple|flags&go=yes`: ONE `remove` of one glyph pair on `flPackage.kerning(current master)`, key `(a, b)` or `((a, False), (b, False))`, with the exact pair and `len()` read before and after (`removed` only when the entry was a number, reads `None` after, and `len()` dropped by exactly 1); the gates of `/debug/trysetkern`; no mark, no panel refresh; 10 per listener run. It CHANGES the font in memory.
- **Kerning group edit probe (v0.199, editing kerning groups, names only 1499–1504):** `GET /debug/trykerngroupedit?op=rename&name=OLD&new=NEW&go=yes` or `?op=remove&name=N&pairs=keep|delete&go=yes`, optionally `&glyph=G`: ONE `rename(OLD, NEW)`, `remove(N)` or `remove(N, True)` on the current master's kerning groups (`flPackage.kerning(master).groups`). The group must be a kerning group confirmed by `items()` and `getAllGroups()`; NEW may not be a glyph name or the name of any group. Read before and after: `items()`, `getAllGroups()`, `len()` of the table and of the groups, and with `glyph` the group's own class entry against G (under both names after a rename). `renamed` / `removed` and `entry_followed` / `entry_gone` come from the re-read only. Exactly one font open; no mark, no panel refresh; 10 per listener run. It CHANGES the font in memory. Run live GE 1505–1522 ([kerning.md](../topics/kerning.md) §18).
- **Kerning panel refresh probe (v0.123, KW, §13):** `GET /debug/trykernrefresh?stage=container|update|changed&go=yes`: ONE `flPackage.kerningContainer()`, then `fontlab.Update(container)` or `container.changed()` once; flags and table size before and after; exactly one font open; 6 per listener run. None of them made the KERNING panel list an API-written pair (553–556).
- **Element box and dependency probe (v0.129, P1.1, [reading.md](../topics/reading.md)):** `GET /debug/tryshapebox?stage=shapebox|dependencies&name=X&go=yes`, read only: ONE `shape.inkBox()` per element of the modern active layer (a real list, at most 20), or ONE `flGlyph.isUnbindedDependecies()`; layer counts and advance width before and after (`side_effect_detected`); exactly one font open; 12 per stage and listener run.
- **Notification probe (v0.131, S1, §2):** `GET /debug/trynotify?stage=state|call&name=X[&which=W][&on=class|instance]&go=yes`: the changed flags and history positions of the package, workspace and glyph; `stage=call` makes ONE `flItems` notification from a fixed list (`changes_applied`, `workspace_has_changes`, `package_updated`, `package_content`, `glyph_updated`), with those reads before and after (`changed_readings`, `side_effect_detected`); exactly one font open; 20 state reads and 3 per call in a listener run. **Since v0.135 (KERNING panel research):** `stage=ids` reads `id` and `fgId` of the package and `id` and `fgGlyphId` of the glyph, then makes one `flWorkspace.findPackageId(n)` per package number that fits a `uint` and one `isEqual` on a result that is not null, with the same reads before and after, 3 per listener run; `which=font_selected` adds `notifyFontSelected(uint)`; `id_from=object|fg` chooses the id passed by `glyph_updated`, `package_content` and `font_selected` (`object` by default) and is refused on a call with no id. A number that is not a plain integer from 0 to 4,294,967,295 is refused before anything is called, so `id_from=object` now refuses the 13-digit object ids.
- **Names probe (v0.137–v0.145, P0.4, [fonts-and-sync.md](../topics/fonts-and-sync.md) §8k):** `GET /debug/trynames?stage=state|set|refresh|store|legacy_set|info_set|title[&field=F&value=V][&which=W][&full=yes|no]`: the package's `psn ffn tfn tsn sgn` and `fileName`, its `info` Preferred family and subfamily (v0.143), and the legacy `font.info` family, style, Full name and PostScript name. `set` makes ONE assignment of one package name (10 per listener run); `refresh` ONE notification, `which=content` (`notifyPackageContentUpdated(fgId)`), `package` (`notifyPackageUpdated(fgId)`), `packages` (`notifyPackagesUpdated()`), `model` (`notifyModelChanged()`), `properties` (`notifyPropertiesChanged(<flPackage>)`), `applied` (`notifyChangesApplied(title, <flPackage>, False)`), `readed` / `added` (`notifyPackageReaded` / `notifyPackageAdded(<flPackage>)`) or `changed` (`flPackage.changed()`), 3 each; `store` ONE `flPackage.store_font_info(<fgPackage>)`, `legacy_set` ONE `font.info.familyName = V` and `info_set` ONE `flPackage.info.F = V` for the Preferred names, `title` ONE `flPackage.title_name(True|False)` (v0.144; the reply holds the returned text and `elidedName` before and after; `state` reads `elidedName` too), 3 each. Every stage but `state` needs `go=yes`; every name is read before and after (`changed_readings`); exactly one font open. `set`, `legacy_set`, `info_set` and `applied` CHANGE the font in memory. **`/debug/tryfont?stage=construct_named&family=F[&mark=yes]&go=yes`** (v0.142; `mark=yes`, v0.145: after the names read back equal, ONE `flItems.notifyChangesApplied(title, <the package just made>, False)` on it): the one `flPackage()` of `construct`, then `tfn`, `ffn`, `psn`, `sgn` as Build Names gives them, each read back; shares the once-per-run limit.
- **Package probe (v0.148 / v0.149, P0.9, [fonts-and-sync.md](../topics/fonts-and-sync.md) §8k):** `GET /debug/trypackage?name=X&go=yes`, read only, any number of fonts open: ONE read of `flGlyph.package` of a glyph of the font in front, that package's `fgId`, path, masters, glyph count and upm, ONE `isEqual` against the current package, the font in front's counts for comparison, `CountFonts()` and the package count before and after. `stage=cached&go=yes` (v0.149): the same for the wrappers already in the listener's cache (at most 20, none built), each checked against its key and `isValid` first. 20 runs per listener run, both stages together.
- **Open contour probe (v0.125, P2.1, [reading.md](../topics/reading.md) §8e):** `GET /debug/tryopen?stage=detached|draw&name=ocp…&kind=line|curve&go=yes`: ONE open contour (never closed; `line` the V of 581, `curve` the arch of 583), built detached and read back, or drawn into an empty glyph whose name starts with `ocp` and read back from the layer (`layer_closed`, `drawn`); exactly one font open; 6 per listener run. `draw` CHANGES the font in memory.

- **Component probe (v0.155–v0.167, P2.7, [reading.md](../topics/reading.md) "Components: placing one through the API"):** `GET /debug/trycomponent?stage=S&target=cpp…&go=yes`; exactly one font open; 6 per listener run, all stages together; every reply has the target's elements, outline and width and the glyph count before and after, and `side_effect_detected`; only a confirmed component is marked. `glyphcomponents` and `shapedata` (`&source=cpp…&dx=&dy=`, v0.155): `setGlyphComponents([GlyphComponent(source)], …)` or `addShape(flShape(<source shape>.shapeData))`. `readcomponents` (v0.156): one read of `layer.components`, read only. `generate` and `setgenerated` (`&recipe=cpp…[%2Bcpp…]`, v0.157–v0.164): ONE `package.generateGlyph`, and for `setgenerated` then ONE `setGlyphComponents` with what it returned; `args=2..5`, `pkg=id`, `int=yes`, `width=int`, `items=id` change one argument each. `auto&step=read|setrecipe|setauto|build` (v0.165): one step of the layer's own recipe build on an empty layer; `build` needs `&recipe=` equal to the layer's recipe; `step=unauto|killauto` (v0.166): `autoLayer = False` or ONE `killAuto()` on an auto layer holding only components of `cpp` glyphs. `offset&how=assign|apply&dx=&dy=` (v0.167): ONE `shape.transform = QTransform(…)` or ONE `shape.applyTransform(…)` on a layer holding one component at identity, `autoLayer` off; `offset_placed` needs the matrix and the element's `inkBox()` to move by the offset. `removeshape&element=I&recursive=0|1` and `clearcomponents` (v0.176, research for removing a component): ONE `layer.removeShape(<component I>, recursive)` or ONE `layer.clearComponents()` on a layer of 1 to 30 components of `cpp` glyphs, `autoLayer` off; `removed` needs exactly the expected components left, unchanged, the layer kept and the sources, width and glyph count unchanged ([CHANGELOG.md](../CHANGELOG.md)). `auto&step=setrecipe|setauto|build|unauto|clearrecipe&nonempty=yes` (v0.180): the same steps on a target that already holds plain contours and / or components of `cpp` glyphs; `existing_kept` compares it with what `setrecipe` recorded in this listener run. `templayer&step=addlayer|build|move|removelayer[&recipe=cpp…]` (v0.181): the temporary-layer route, one step per request: a layer `gb_temp_component` added to the target, the recipe build there, its component added to the working layer, the layer removed; its own 10 calls per listener run; marked only when `removelayer` leaves the working layer as recorded plus one new component; `step=activate` (v0.182): ONE `working_layer.setActive()`; since v0.183 `placed_beside` also needs the new component to name the working layer (`component_layer_matches`). `fixlayer&element=I` (v0.183): ONE `shapeData.componentLayer = <the target's layer name>` on component I; its own 6 calls per listener run. `templayer&step=setlayer` (v0.184): the same assignment on the temporary layer's component, before `move`; `step=droptemp` (v0.184, no baseline needed): an empty `gb_temp_component` left behind is removed, after `setActive()` of the other layer when it is active. `templayer&brush=yes` (v0.185): the working layer may also hold Power Brush or other composite shapes, never given an `inkBox()` call; `&sync=light`: the step's sync check, and the guard before a later `font.update()`, read only `glyph.width` and the modern layer (light kind `trycomponent_light`), `sync=full` (default) the full check; its own 20 calls per listener run. Every stage but `readcomponents`, `generate` and `step=read` may CHANGE the font in memory.
- **Feature code probe (v0.107 / v0.108, K11, [kerning.md](../topics/kerning.md) §11):** `GET /debug/features?stage=tags|size|shape|lines[&tag=T][&contains=a,b,c]&go=yes`. `tags`: one `font.features.keys()`, the tags and their count. `size`, `shape` and `lines` also call `has_key(T)` (only for a listed tag) and `get_feature(T)` (only when that is True), then return only the size, or the line counts by kind with the first 300 characters, or the lines naming 1–3 names (at most 20 per name, cut at 200 characters). One-font gate, 10 requests per listener run in all stages together, `len(features)` before and after. Never called: `clear`, `remove`, `set_feature`, `set_prefix`, `get_prefix`.

- **Kerning research probes (v0.90 to v0.93, section 8p; kept as evidence tools):** `GET /debug/fontdir?stage=dir|sub|member[&attr=NAME][&members=a,b,c]` (names only: public names, type, `len`, docstrings of ONE font attribute and at most 8 of its members; never calls anything); since listener 0.115 / 0.116 `stage=memberdir&members=PATH` (one member, or a dotted path of up to 3 steps, one level deeper: type, docstring, public names; no value, no call, no `len`); since 0.117 `stage=keys&members=PATH&go=yes` (GATED: one `keys()` call on the object at the end of the path; text lists only; research N1 in [LIVE-TESTS.md](../LIVE-TESTS.md)); `GET /debug/trykern?a=NAME&b=NAME&go=yes` (one `font.kerning.get((a, b))`, 20 calls per listener run, both names must be glyph names); `GET /debug/trygroups?go=yes[&contains=a,b,c]` (one `font.groups.getCompiled()`, 10 per run, returns only a 500-character head or the matching segments). The product route `/kerning/pairs` does not need them.
- **Advance-width probe (v0.196, goal 6 of [PROJECT.md](../PROJECT.md), [FONTLAB-API-RULES.md](../FONTLAB-API-RULES.md) §10):** `GET /debug/tryadvancewidth?name=tri…&stage=names|read[&go=yes]`; exactly one font open; `names` lists the member names of the glyph's `flGlyph` wrapper; `read&go=yes` reads `flGlyph.advanceWidth` once (10 per listener run, counted before the read), with the glyph count before and after (`side_effect_detected`). Not run live (1437 was names only through `/debug/moddir`).
- **Self-closing dialog probe (v0.201, research for the client's time limit, §2):** `GET /debug/trydialogtimeout?how=slot|python&seconds=3..50&go=yes`; UI only, no font call; ONE test Yes/No dialog (default No) with a single-shot `QTimer` owned by it, connected to the dialog's `reject()` (`slot`) or to a Python function that calls it (`python`); the reply gives `elapsed_s`, `exec_result`, `result_is_yes`, `clicked_button`, `closed_without_click`, `dialog_result`, `timer_active_after` and, for `python`, `timer_fired`; 10 per listener run, counted before the dialog. Names only 1588 (`QTimer`), 1589 (`QMessageBox` in `PythonQt.QtGui`). Run live SC 1590–1593 ([LIVE-TESTS.md](../LIVE-TESTS.md)): both forms closed a waiting dialog on time (10.0 s, 10.015 s), and clicks in time counted as usual; 0.201 could not read the clicked button's label (`text` is a property in PythonQt, not a method), 0.202 reads the property. Since v0.202 `&countdown=yes`: a second timer owned by the dialog relabels the No button "No (N)" once a second through a Python function (`button(QMessageBox.No).setText`); visual only: a failure is reported as `countdown_error` and the dialog still closes on time; the reply adds `countdown_ticks`, `countdown_last_label`, `countdown_label_after`. Names only 1594, 1595; run live CD 1596–1598: the label counted down visibly each second, the dialog closed on time, Yes and No in time as usual.
