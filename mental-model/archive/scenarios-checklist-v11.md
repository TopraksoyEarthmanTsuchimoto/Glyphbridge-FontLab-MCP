# Glyphbridge — scenario checklist (test matrix)

Goal: an agent must read *any* glyph in FontLab accurately. A scenario counts as supported only when the tool's answer matches
FontLab's own numbers; until then the tool must say `unverified`, never guess. Status as of listener v0.95 / server v0.31 (v11 update: header and rows 33, 57 and 61 revised, rows 65-80 added = the kerning scenarios K1-K16 of milestone summary v11, section 14; v10 update: rows 33, 47 and 52 revised, rows 53-64 added; every other row keeps its v0.82 / v0.26 status unless it says otherwise; v8 update: rows 30, 31, 33, 36, 39-42 revised, rows 47-52 added; priorities follow section 14 of the v8 summary) (rows 1-21 are the READING and name/Unicode/save scenarios of v0.51 / v0.18, unchanged; rows 22-33 are the geometry WRITING scenarios added for v0.52-v0.75, updated for curves; rows 34-46 are the CURVE and layer-guard scenarios added for v0.76-v0.82). Optional companion of milestone summary v11 (its TO DO list, section 14, orders the open rows: the kerning rows 65-80 come FIRST by the user's decision of 2026-10-27); the summary alone is enough to continue.

## Procedure for each scenario

1. Build a small reference glyph in the test font (Font > New Glyph… > **Create Blank**; copy shapes with right-click > **Copy Element**).
2. In FontLab note: the X/Y readout of 2–3 nodes (select with the Contour tool), the transform bar values (Element tool), and LSB/RSB
   (shown truncated; the exact values come from the API).
3. Run `.\venv\Scripts\python.exe glyphbridge_mcp_server.py --check --outline NAME` and compare.
4. Record the result here and add the case to `tests/` (embed the captured node data in the test script, then add the expected output) so it stays covered. Glyphbridge never saves (save policy, v0.18): YOU save the reference font (File menu or Ctrl+S) only after building reference glyphs by hand, never after a live write test (quit FontLab without saving instead), and
   keep a backup of `savedtestfont.vfc` before every live round.
