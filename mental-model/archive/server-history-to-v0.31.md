# Server version history up to v0.31

The module docstring of `glyphbridge_mcp_server.py` as it stood at v0.31 (commit 8d464b0), unchanged. Its history part was removed in v0.32. Newer versions: [CHANGELOG.md](../CHANGELOG.md).

Glyphbridge-FontLab-MCP  -  MCP server (v0.31)
===============================================
(v0.31: get_kerning has NO upper limit on the number of pairs any more; instead there is an APPROVAL THRESHOLD of 250 pairs (for text: 251 characters). A request for more pairs is refused BEFORE anything is sent, with a message that tells the agent to warn the person (a large read costs many tokens), say how many pairs and why, and ask for approval; only after the person has said yes may the agent repeat the call with confirmed_large_read=true. The flag is the agent's own statement that the person approved: a tool cannot check that. The request now travels as a POST with a JSON body (a web address cannot carry thousands of pairs) and needs listener v0.95; the waiting time grows with the number of pairs. Still a pure read. (v0.30: NEW read-only tool get_kerning(pairs=None, text=None): FontLab's own kerning value for a FEW selected glyph pairs (at most 40), never the whole table. pairs is a list of [left, right] glyph names; text is a short string (2 to 41 characters) whose neighbouring characters are looked up (each character is mapped to the one glyph whose primary Unicode it is). Class (group) kerning is included: the listener (v0.94 or newer, GET /kerning/pairs) asks font.kerning.get((left, right)), which FontLab resolves across glyph, group and group-to-group kerning (checked against FontLab's KERNING panel). A pair FontLab has no entry for answers value 0, kerned false; a pair that could not be read answers an error and is NEVER a zero. The reply carries units_per_em, table_size and the listener's side_effect_detected check, and an agent_instruction that says what is NOT covered (feature / contextual kerning, multi-master). A pure read: no change counter, no save. MIN_LISTENER_VERSION stays (0, 82); get_kerning checks for listener 0.94 BEFORE sending. (v0.29: the write tools forward the listener's v0.89 fontlab_sync block (attempted, synced, verdict, call_error, reason): since listener 0.89 FontLab syncs a drawn or changed glyph by itself right after the write, so synced_with_fontlab is normally true and no editor tab is needed; the old 'open the glyph in an editor' advice is only given when Glyphbridge's own sync attempt did not reach 'synced'.)

An older listener sends no margins_agree, so the v0.25 check (stale_legacy_view, unverified) still applies. MIN_LISTENER_VERSION stays (0, 82).)

(v0.23: CURVES. NEW tool draw_path(name, contours) draws closed contours with CUBIC curves into an empty glyph. RULE B: the listener rounds every coordinate to the nearest whole unit (a half rounds up) and the reply lists every coordinate it changed in coordinates_rounded; draw_polygon follows the same rule and reports the same list (before, FontLab rounded silently and only counts were checked). A smooth node needs its two neighbours (handle or neighbouring point) on opposite sides of one straight line through it (within 2 degrees), otherwise nothing is drawn. Success (verified) needs the re-read modern layer to match the request node by node (nodes_match). MIN_LISTENER_VERSION is now (0, 81); draw_path checks the listener version BEFORE sending. (v0.22: SEVERAL CONTOURS, AND A CLEARER DIRECTION NOTE. draw_polygon(name, points=None, contours=None) now also takes `contours`, a list of 1 to 20 point lists (3 to 500 points each, at most 2000 in total), drawn as ONE shape, e.g. a letter with a counter; give exactly one of points / contours. The reply adds contours and contour_sizes and verifies 1 shape, the node total and the contour count. Direction: live (two glyphs, both ways round) FontLab's own clockwise flag reads the OPPOSITE of the geometric direction in y-up font units (a counterclockwise contour reads clockwise: true), and the outer contour of the real glyph A of the cubic test font is counterclockwise. get_glyph_outline therefore reports direction_computed (geometric) and clockwise_reported, treats the inverted flag as the expected case (flag_follows_known_inversion) and warns only when it is NOT inverted; draw_polygon says outer contours counterclockwise, counters clockwise. MIN_LISTENER_VERSION is now (0, 75). (v0.21: OUTLINES DRAWN THROUGH THE API CAN BE READ BACK. get_glyph_outline no longer refuses when the legacy reader is blind or stale: the listener (v0.74) then also sends the nodes of FontLab's MODERN layer, and the tool returns them with source "modern layer": every contour (closed, FontLab's clockwise flag, and the direction computed from the points), every node (x, y, On / Off, curve, smooth), the ink bounding box and the modern margins. verification is "verified" only for straight-segment outlines whose bounding box equals the modern left sidebearing and ink width; with curves it is "unverified" (the curve extents are not computed on this route). MIN_LISTENER_VERSION is now (0, 74). (v0.20: GLYPHS NEVER OPENED IN AN EDITOR, AND A DRAWING TOOL. Runs in your normal venv (MCP SDK v2). Claude Desktop launches it over
stdio. It does NOT talk to FontLab directly: it asks the Glyphbridge
listener (glyphbridge_fontlab_mcp_listener.py, running inside FontLab) over
http://127.0.0.1:8765 and relays what comes back.

Design rule: a tool only returns data if the listener actually answered
with valid data. Anything else - FontLab closed, listener not started,
timeout, bad response, no font open - raises a ToolError with a plain
explanation. There is no code path that reports success without data.

Never print() to stdout in this file: on stdio, stdout IS the protocol.
Logging goes to stderr.

Self-check without Claude (listener must be running in FontLab):
    python glyphbridge_mcp_server.py --check
    python glyphbridge_mcp_server.py --check --outline A      (also dumps one glyph's analysed outline)
    python glyphbridge_mcp_server.py --check --notdef-warn    (also runs check_notdef: MAY SHOW the warning dialog in FontLab)
